# 洪荒 · 世界

> 一个以中国神话为隐喻、全中文标识符书写的 Rust workspace 项目——用「治理内核 + 4 分类 LLM 流水线」构建一个能自我开发、自我治理的软件世界。

**当前版本**：`v0.2.0`（阶段 3 自举）
**项目代号**：洪荒 · 世界
**许可证**：MIT OR Apache-2.0（双许可）

---

## 项目是什么

「洪荒 · 世界」是一个用 Rust 语言书写的 **cargo workspace**，共 **22 个 crate**。
它把软件开发本身抽象成一场「开天辟地」的创世过程：

- **治理内核**：一套规则注册表（RULE_REGISTRY）+ 决策契约，约束项目的每一次演进；
- **4 分类 LLM 流水线**：将任务按 4 类角色卡切分，由大语言模型（MiniMax-M3）接力协作完成开发；
- **六层目录结构**：维度 → 域 → 府 → 殿 → 阁 → 园，每一层都有明确的职责边界；
- **36 格位记忆体系**：以 SQLite 持久化「经 / 权 / 行」三档记忆，支撑 AI 自主理解项目、复盘归档。

项目定位可概括为：**「9 根维度 + 6 层结构 + 4 分类抽象」**。

### 核心特性

| 特性 | 说明 |
|:--|:--|
| 全中文标识符 | 代码变量、函数、模块名、注释全部使用中文，对非程序员友好 |
| Rust workspace | 22 个 crate，`cargo build` / `cargo test` 一键完成 |
| SQLite 持久化 | 经 `rusqlite` 的 `bundled` 特性内置，**无需额外安装数据库** |
| 真实 LLM 接入 | MiniMax-M3，通过环境变量配置，无密钥自动降级 mock |
| 自举能力 | 项目可「让 LLM 自己写新 crate 并自动提交」，具备自我开发雏形 |
| 一键全验 | 17 项门禁（格式 / 测试 / 命名 / 治理等）一键跑通 |

## 目录结构总览

项目采用**六层目录结构**，从宏观到微观逐层收束，每一层的命名都遵循「祖孙不同名、同层全局唯一」的约束：

| 层级 | 示例 | 含义 |
|:--|:--|:--|
| **维度**（顶层根目录） | `乾坤`、`鸿蒙`、`证道`、`道韵`、`道果树` | 哲学层面的划分，承载不同领域的根 |
| **域**（第二层） | `界面呈现-域`、`基础设施-域`、`质量门禁-域` | 领域划分，界定一组相关能力 |
| **府**（第三层） | `命令操作-府`、`模型连接-府` | 功能府邸，**每个府对应一个 crate** |
| **殿**（第四层） | `命令-调度-殿`、`命令-数据-殿` | 职责殿堂，模块级划分 |
| **阁**（第五层） | `命令-核心-阁`、`帮助-生成-阁` | 方法契约，定义一类功能面 |
| **园**（第六层） | `命令-实现-园`、`帮助-文本-园` | 实现实例，承载具体落地代码 |

> 一条完整路径示例：
> `乾坤/界面呈现-域/命令操作-府/命令-调度-殿/命令-核心-阁/命令-实现-园/核心.rs`

### 主要顶层目录

| 目录 | 含义 |
|:--|:--|
| `乾坤/` | 空间维度：界面呈现-域（命令操作-府） |
| `鸿蒙/` | 地基维度：基础设施-域（14 府）+ 世界配置-域（配置管理-府） |
| `证道/` | 磨难维度：验证-域（单元测试-府）+ 质量门禁-域（监控 / 校验 / 评估 / 门禁） |
| `道韵/` | 法则维度：律法-域（规则-府，RULE_REGISTRY） |
| `道果树/` | 构建产物维度：构建物-域（debug / doc / release，无府） |
| `世界/` | 二进位入口（生产 CLI，可执行文件名为 `shijie`） |
| `传承殿/` | 文档与决策殿堂（项目叙述、决策契约、历史文档） |

## 环境要求

- **Rust 1.75+**（工作区声明的最低版本），建议使用最新稳定版；
- **SQLite**：经 `rusqlite` 的 `bundled` 特性内置编译，**无需额外安装**；
- **真实 LLM（可选）**：接入 MiniMax-M3 需要以下环境变量：

| 环境变量 | 说明 |
|:--|:--|
| `LLM_BASE_URL` | LLM API 端点地址 |
| `LLM_MODEL` | 模型名称（如 `MiniMax-M3`） |
| `LLM_API_KEY` | API 密钥（设置后即可解锁真实调用） |
| `LLM_BACKEND` | 后端模式：`real`（真实）/ `mock`（模拟）。默认真实，无密钥时自动降级 mock |
| `LLM_TIMEOUT_MS` | 请求超时（毫秒） |

> 不设置任何 LLM 环境变量也能构建、测试、运行全部门禁——此时流水线走 mock 后端。

## 快速开始

```bash
# 1. 克隆仓库
git clone <仓库地址>
cd <项目目录>

# 2. 构建整个工作区
cargo build --workspace

# 3. 运行全部测试（约 515 项）
cargo test --workspace

# 4. 一键全验（17 项门禁）
#    Windows（PowerShell）：
powershell -NoProfile -ExecutionPolicy Bypass -File 一键全验.ps1
#    Linux / macOS / Git Bash：
bash 一键全验.sh

# 5. 运行 CLI（查看帮助）
cargo run -p shijie -- 帮助
```

构建产物为可执行文件 `shijie`（位于 `target/debug/` 或 `target/release/`），
也可直接 `cargo run -p shijie -- <命令>` 调用。

| `跳层测试` | — | 跳层拒绝路径 |
| `反序测试` | — | 反序拒绝路径 |

### 命令示例

```bash
# 查看帮助
shijie 帮助

# 环境就绪检查
shijie 就绪

# 工作空间健康快照
shijie 状态

# 跑一个任务（4 分类流水线）
shijie 跑 --task=任务标识

# 端到端 mock LLM 流水线
shijie 端到端

# 部署健康检查（返回退出码 0 表示健康）
shijie --health

# 记忆：三档投影
shijie 记忆 三档

# 记忆：播种 36 格位
shijie 记忆 播种

# 记忆：格位统计
shijie 记忆 统计
```

### 退出码语义

统一退出码约定（杜绝魔数）：

| 退出码 | 含义 |
|:--|:--|
| `0` | 成功 |
| `1` | 命令参数错误 |
| `2` | 材料输入错误 |
| `3` | 状态机违规（跳层 / 反序 / 循环未触发升级） |
| `4` | 模型故障（无密钥 / 限流 / 超时 / 非 2xx） |

## 一键全验 17 项门禁

`一键全验.ps1`（Windows）/ `一键全验.sh`（Linux）串联以下 17 项质量门禁：

| 编号 | 门禁 | 说明 |
|:--|:--|:--|
| 1 | 格式 | `cargo fmt --check` |
| 2 | 静态分析 | `cargo clippy -D warnings` |
| 3 | 单元测试 | `cargo test --workspace` |
| 4 | 编译 | `cargo check` |
| 5 | 文档 | `cargo doc` |
| 6 | 安全审计 | `cargo audit`（离线） |
| 7 | 依赖审查 | `cargo deny`（离线） |
| 8 | 无 src/ 平铺 | 六层目录结构约束 |
| 9 | 无空目录 | 目录整洁约束 |
| 10 | 无临时目录残留 | 无垃圾文件 |
| 11 | 决策契约 | 决策文件字段校验 |
| 12 | 命名唯一性 | 祖孙不同名 + 同层唯一 + 无英文白名单 |
| 13 | 防退化 ≥2 殿 | 每个府级 crate 至少 2 殿 |
| 14 | 格位稀缺 36 上限 | 记忆格位数量契约 |
| 15 | 文档收割门防污染 | 文档清洁度校验 |
| 16 | 治理审计 | 治理规范审计 |
| 17 | 标识符中文 | 代码标识符须为中文 |

> 所有 17 项门禁通过后，脚本输出「通过 17 / 失败 0」，并以退出码 `0` 结束。

## 技术栈

- **语言**：Rust（edition 2021，rust-version 1.75）
- **工程组织**：cargo workspace（34 个 crate）
- **持久化**：SQLite（`rusqlite` 0.32，`bundled` 特性）
- **LLM**：MiniMax-M3（OpenAI 兼容接口，Bearer 认证）
- **网络**：`ureq` + `serde_json`
- **异步 / 日志**：`tracing` + `tracing-subscriber`
- **错误处理**：`thiserror` + `anyhow`
