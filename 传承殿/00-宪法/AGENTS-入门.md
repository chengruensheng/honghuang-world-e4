# AGENTS-入门.md

> **原语**：本项目沿用的创世叙事词汇，仅用于命名与溯源。
> **工程理解词语**：将原语翻译为可精确执行、可验证的工程术语；本文正文一律使用工程理解词语，原语仅在《术语对照表》中保留。
> 术语对照见 `传承殿/00-宪法/术语对照表.md`。

> **新 AI 助手 / 人类协作者 5 步入门**——任何加入知识库项目的协作者必读。

## 一、为什么需要这份文档

知识库是**哲学先于代码**的项目。新协作者如果直接看代码，会被具体命名误导；必须先理解哲学推导，才能做出与现有决策一致的设计。

入门路径**不可跳步**——跳步等于没入门。

## 二、5 步入门

### 第 1 步：项目本质（30 分钟）

读：
- `README.md`（项目入口）
- `00-宪法/AGENTS.md`（18 条强制规则）
- `00-宪法/CHARTER.md`（目标 + 非目标 + 边界）

理解：
- 知识库 = 承认治理自身也不完备的多角色协作系统
- 9 根维度 + 6 层结构 + 4 分类 + 决策契约
- 不沿用任何借来的词；每个命名必须哲学推导

### 第 2 步：哲学层（1 小时）

读（按顺序）：
- `01-哲学/01-世界观.md`——9 根维度 + 6 层结构 + 4 分类抽象 + 流水线
- `01-哲学/02-治理哲学.md`——治理哲学 5 工程基线 + 4 禁止 + 5 法 + 元三治
- `01-哲学/03-工程哲学.md`——DSH 6 子系统 + 3 类事件 + 2 模式 + 完整验证流水线

理解：
- **六柱石**：架构根本 / 方法论原则 / 工程实现 / 检验 / 应变 / 元治理
- **五法**：尊重因果顺序 / 恰到好处 / 明确边界 / 定向调节 / 力度适配阶段
- **决策可证伪 + 历史不可篡改** 是治理的根基

### 第 3 步：概念层（2 小时）

读 `02-概念/` 全部 8 份（按顺序）：

1. `01-可插拔.md`——不是「乐高」，是「系统长期演化需局部替换」
2. `02-流水线.md`——不是「4 类角色」，是「多角色分工比单角色更可靠」
3. `03-记忆.md`——36 上下文槽位 + 3 档投影 + 3 源记录 三维正交
4. `04-事件流.md`——三类事件 + 哈希链 + 历史记录不改
5. `05-追问.md`——4 问题（道二 / 尊重因果顺序 / 恰到好处 / 明确边界）+ 不调 LLM 生成内容
6. `06-规则注册表.md`——RULE_REGISTRY 单一真相源 + 派生值
7. `07-不可逆结果.md`——哈希校验 + append-only
8. `08-验证分离.md`——验证者与生成者必须分离

理解：每个概念都是**哲学 → 概念 → 工程** 三层推导。

### 第 4 步：决策层 + 设计层（1 小时）

读：
- `03-决策/已定/` 全部已定决策
- `04-设计/01-架构总览.md`
- `04-设计/接口契约/01-插件-manifest.md`
- `02-概念/流水线/02-流水线.md`（流水线状态机）
- `02-概念/记忆/03-记忆.md` + `02-概念/事件流/04-事件流.md`

理解：
- 决策契约 = decided_by + falsifiable + implements + upstream
- 流水线状态机不可跳层不可反序
- 事件流哈希链 + 历史记录不改

### 第 5 步：质量 + 治理（30 分钟）

读：
- `06-治理/01-司衡基线承接.md`（5 基线 + 4 禁止）
- `06-治理/04-元三治.md`
- `00-宪法/AGENTS-风格契约.md`（17 项门禁 + 垃圾清理）

理解：
- 完整验证流水线 = 工程质量唯一标尺
- 元三治 = 治理的治理

## 三、入门后第一周

新协作者第一周只能：

- **修 bug**——按 `02-概念/` 现有概念找根因
- **补测试**——按 `02-概念/` 对应概念写概念测试
- **补文档**——按 `00-宪法/格式规范模板.md` 补格式

**不能**（按 AGENTS 禁止条款）：
- ✗ 擅自动用户数据（`.上下文/状态/*.jsonl`）
- ✗ 擅自 commit「世界自转产物」
- ✗ 擅自修改核心规则（RULE_REGISTRY）
- ✗ 替项目负责人拍板（重大决策必须问过才做）

## 四、入门后第二周

提交**第一个 PR**：

1. 选一个 P0 改造项（接 `03-决策/已定/`）
2. 先入稿（在对应设计稿章节落笔）
3. 再落码（完整验证流水线 17 项全过）
4. 提交决策文档（带 decided_by + falsifiable）

## 五、风格契约（必读）

详见 `00-宪法/AGENTS-风格契约.md`——包含 6 条风格 + 4 条垃圾清理。

## 六、新决策的进入流程

遇到新决策时：

1. **写决策草案**（`03-决策/待定/`），stage = 1/3
2. **列出 falsifiable** + 时间窗口
3. **找上游决策**（upstream）
4. **找哲学锚**（implements：六柱石 或五法之一）
5. **找 decided_by**（人类标识符，必填）
6. 提交给项目负责人审 → stage = 2/3 → stage = 3/3

## 七、常见错误

### 错误 1：直接落码

> 「我先写代码，回头补文档。」

✗ 违反 AGENTS 强制规则 13「先入稿再落码」。
✓ 先在对应设计稿章节落笔，再实现。

### 错误 2：擅自命名

> 「我叫它 X，你看行不行。」

✗ 命名必须哲学推导，不是 AI 决定。
✓ 先回答「为什么叫这个」，再命名。

### 错误 3：改核心规则

> 「我觉得 13 条红线不合理，要改。」

✗ 违反治理哲学基线 1 + AGENTS 禁止条款。
✓ 写新决策文档覆盖，旧决策不删。

### 错误 4：借来已有命名

> 「这个像 X 项目里的 Y，就叫 Y 吧。」

✗ 借来的词是 AI 协作的陷阱。
✓ 从哲学推导新命名，不沿用。
