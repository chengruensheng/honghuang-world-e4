# AGENTS-风格契约.md

> **风格一致 + 垃圾清理**——所有协作者必读必守。

## 一、为什么需要风格契约

传承殿是**多人多 AI 协作**的项目。没有风格契约，不同协作者会产生：
- 命名混乱（一个概念多种叫法）
- 注释冗余（AI 味的解释）
- 临时文件堆积
- 未使用代码堆积
- 测试与概念脱节

风格契约的目的是**让所有产出看起来像一个人写的**。

## 二、6 条风格（必守）

### 风格 1：哲学推导先行

> 每个命名、每个设计决策，必须先回答"为什么"。

```
✗ 错误：直接命名 X，不解释
✓ 正确：先哲学推导 → 命名 X，引用哲学锚
```

### 风格 2：客观陈述而非主观

> 用第三人称中性句式，只留可复用的事实/决策/规则/路径。

```
✗ 我觉得这个设计不错，因为...（第一人称 + 主观）
✓ 此设计接 02-概念/01-可插拔.md，满足 5 法之顺势。
```

### 风格 3：禁止 AI 语气

> 命名与注释严禁 AI 味的修辞。

禁词清单：
- "智能" / "智慧" / "自动"（除非真有 AI 含义）
- "高效" / "强大" / "完美"（除非有数据支撑）
- "优雅" / "简洁"（除非有 falsifiable 论证）
- "我们" / "我"（改用"传承殿"或具体分类）

### 风格 4：可证伪优先

> 每个决策、每条规则、每个机制都有 falsifiable。

```
✗ 这个设计很好（无 falsifiable）
✓ 此设计上线后 3 个月内，插件替换不影响其他插件的成功率 > 95%
```

### 风格 5：痕迹 > 记忆

> 所有重要信息必须落文档，不靠会话记忆。

```
✗ 会议口头决定（无留痕）
✓ 决策文档 03-决策/已定/260826-XXXX-{slug}.md
```

### 风格 6：简化 > 复杂

> 一次改 1-2 个文件，不批量。commit message 简洁（< 200 字符）。

```
✗ 一次性改 10 个文件（无法追溯）
✓ 分 5 个 commit，每个改 1-2 个文件
```

## 三、4 条垃圾清理（必做）

### 清理 1：临时文件清理

**触发时机**：每次 commit 前

**清理对象**：
- `临时文件夹/` 下的过期脚本、临时监控、调试日志
- `.test-tmp/` `.tmp/` 等临时目录
- `*.bak` `*.old` `*.swp` 备份文件
- 调试用的 `console.log` `println!("debug")`

**命令**：
```bash
pwsh 证道/质量门禁-域/门禁-府/验证-临时目录.ps1
```

### 清理 2：未使用代码清理

**触发时机**：每个 Phase 结束

**清理对象**：
- 未使用的 pub 函数/结构体（`cargo machete` 检测）
- 注释掉的代码（用 git 历史代替）
- 死代码（`#[allow(dead_code)]` 警告）
- 重复实现（多个函数做同一件事）

**命令**：
```bash
cargo machete  # 检测未使用依赖
cargo clippy --workspace -- -W dead_code
```

### 清理 3：命名一致性清理

**触发时机**：每个 Phase 结束 + 每次大重构前

**清理对象**：
- 命名不一致（同一概念不同叫法）
- 借来的词（"乐高"、"工具 manifest" 等）
- AI 味命名（"智能-xxx"、"自动-xxx"）

**命令**：
```bash
grep -r "智能-" --include="*.rs" .
grep -r "工具 manifest" --include="*.md" .
grep -r "乐高" --include="*.md" .
```

### 清理 4：文档-代码一致性清理

**触发时机**：每次 docs/ 修改后

**清理对象**：
- 文档提到的接口/字段名与代码不一致
- 文档的 falsifiable 已过期
- 文档引用的决策 ID 不存在
- 入稿点链接断裂

**命令**：
```bash
pwsh 证道/质量门禁-域/门禁-府/验证-AGENTS-一致性.ps1
```

## 四、一键全验（必过）

每次 commit 前必跑：

```bash
bash 一键全验.sh
```

10 项门禁（详见 `05-质量/02-一键全验.md`）：
1. 格式
2. 静态分析
3. 单元测试
4. 编译
5. 文档
6. 安全审计
7. 依赖审查
8. 无 src/ 平铺
9. 无空目录
10. 无临时目录残留

**10/10 全过才允许 commit**。

## 五、commit message 规范

```
<类型>(<范围>): <一句话说明>

<类型>：
- feat：新功能
- fix：bug 修复
- docs：仅文档
- refactor：重构（无新功能无 bug 修复）
- test：仅测试
- chore：构建/工具链

<范围>：
- 模块名（按 04-设计/）

<一句话说明>：
- 不超过 50 字
- 用动词开头
- 避免 AI 味

<body>（可选）：
- 不超过 200 字
- 解释为什么
- 关联决策 ID
```

### 示例

```
feat(记忆承载): 36 格位三维正交数据模型

实现 6 范畴 × 6 格位 + 3 档投影 + 3 源记录。
关联决策：260826-2210-4-分类抽象 + 260826-2220-治理-司衡
```

## 六、复查清单（commit 前自查）

- [ ] 一键全验 10/10 全过
- [ ] commit message 符合规范
- [ ] 命名符合哲学推导（不是借来的词）
- [ ] 注释无 AI 味
- [ ] 临时文件已清理
- [ ] 决策契约完整（decided_by + falsifiable + implements）
- [ ] 入稿点引用正确
- [ ] 文档-代码一致

## 七、违反后果

| 违反级别 | 后果 |
|:--|:--|
| **L1 命名不当** | commit 被拒 + 要求修改 |
| **L2 风格不符** | PR review 被拒 + 要求修改 |
| **L3 核心规则擅改** | commit 回滚 + 决策失效 + 警告 |
| **L4 文档污染**（章节级损坏） | 立即回滚该文件 + 停止当轮（接 AGENTS § 13） |
