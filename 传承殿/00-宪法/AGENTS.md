## 二、强制规则（18 条 = 5 基线 + 4 禁止 + 5 决策 + 4 命名）

### A. 5 工程基线（来自司衡）

1. **确定性程序是治理操作唯一执行者**——LLM 只生成符号材料，不拥有写入知识包 / 事件流 / 决策契约的权限。
2. **信息洪流是旧仓库失败根因**——治理系统必须假设人类注意力稀缺，将介入点限制在异常。
3. **人类只看异常，不看原始日志**——所有 LLM 输出需有摘要 + 异常自动上报。
4. **可验证性约束**——操作来源可追溯、结果可机械校验、历史不可篡改（frozen outcome）。
5. **治理延伸是减少 LLM 参与**——关键决策（任务准入校验 / 验收驳回 / 最终裁决）必须确定化。

### B. 4 禁止条款（来自司衡）

6. **LLM 不可直改知识包**——所有写入需经 decided_by 字段校验。
7. **不可复现的多 Agent 交互不可作治理决策依据**——关键决策需多 LLM 投票 + 阈值。
8. **治理操作必入事件流，留痕不可篡改**——frozen outcome + 哈希链。
9. **人类仅通过异常摘要介入**——项目负责人不直接查看原始对话，只查看异常告警。

### C. 5 决策契约（v3 新增）

10. **每决策带 decided_by**——缺失则事件拒收。
11. **每决策带 falsifiable**——可证伪命题 + 证伪方法 + 时间窗口。
12. **每决策可追溯到哲学锚**——implements 字段必须引用道/法/术/鉴/应/元之一。
13. **先入稿再落码**——新设计先入对应设计稿章节，再实现。
14. **文档收割门**——AI 改任何 .md 必须 diff 对比；`[object Object]` / 内容断崖缩水 / 章节级损坏 → 立即回滚。

### D. 4 命名规则（v3 新增）

15. **不沿用借来的词**——拒绝「乐高」、「工具 manifest」等未推导的命名；每个命名必须能回答「为什么叫这个」。
16. **哲学推导优先**——每个概念必须先写哲学层（为什么）→ 概念层（是什么）→ 工程层（怎么实现）。
17. **中文标识符**——目录用连字符，Rust 模块用下划线，`#[path]` 桥接。
18. **严禁 src/ 平铺**——每个 Rust crate 内部只能有 src/lib.rs（入口）或 src/模块名/mod.rs（嵌套模块），禁止 src/foo.rs 平铺；项目根目录严禁 src/ 目录。

### 命名白名单（中文目录名）

允许英文：SQLite、P0、P1、P2、P3、CI/CD 类标准词。其他情况禁止英文。

祖孙三层语义判据：阁 = 方法契约（接口），园 = 实现实例，核心名必须不同（如「写入方法阁」vs「写入实现园」可，但「写入阁」vs「写入园」违规）。

### 6 层结构模板（府 ≥2 殿 ≥2 阁 ≥1 园）

参考 16-统一六层风格-实施方案.md。新建 crate 必须遵循：府 = lib 入口（pinyin_xxx_fu 命名）；殿 ≥2，每个殿 ≥2 阁（拒绝单链中间层）；阁 ≥1，每个阁 ≥1 园。

### 跨 crate 命名唯一（v3 规则）

同名阁不能在两个不同殿下存在（例：命令元数据-殿/状态-阁 + 命令调度-殿/状态-阁 违规 → 后者改名「自检-阁」）。
