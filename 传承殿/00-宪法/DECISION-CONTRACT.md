# DECISION-CONTRACT.md · v3

> **决策契约**——所有治理动作必须按本契约留痕。

## 一、为什么需要决策契约

司衡工程哲学的核心理念：**治理动作必须可追溯**。如果决策没有契约，治理层无法：
- 验证决策是否被正确执行（falsifiable）
- 追溯决策的负责人（decided_by）
- 评估决策是否符合哲学锚（implements）

## 二、决策文档模板

```markdown
---
id: YYMMDD-HHMM-{slug}
title: {一句话决策标题}
stage: {1/3 提案 | 2/3 审阅 | 3/3 拍板}
decided_by: {人类标识符，必填}
falsifiable:
  - 命题: {可证伪命题}
    证伪方法: {机械判定 | 人工统计 | 文档审查}
    时间窗口: {N 个月}
upstream: {上游决策 id 或 N/A}
implements: {道 | 法 | 术 | 鉴 | 应 | 元 或对应哲学锚如"顺因"/"有度"}
decided_at: {YYYY-MM-DD}
---

## 背景

{为什么需要这个决策。可引用 AGENTS.md / 司衡 / DSH / 其他决策。}

## 方案

{具体方案 + 备选方案 + 不采纳理由。每备选方案列出对应哲学锚。}

## 后果

{正面后果 + 代价与风险。每项需可量化或可观察。}

## 可证伪条件验证

{上线后定期检查 falsifiable，记录验证结果。}
```

## 三、字段约束

| 字段 | 必填 | 说明 |
|:--|:--|:--|
| id | ✓ | YYMMDD-HHMM-slug 格式，slug 必须唯一 |
| title | ✓ | 一句话，不超过 30 字 |
| stage | ✓ | 1/3 提案 / 2/3 审阅 / 3/3 拍板 |
| decided_by | ✓ | 人类标识符；不能是 LLM 名字或角色名 |
| falsifiable | ✓ | 至少 1 条可证伪命题 |
| upstream | ✓ | 上游决策 id 或 N/A |
| implements | ✓ | 哲学锚（道/法/术/鉴/应/元 或五法） |
| decided_at | ✓ | 决策日期 YYYY-MM-DD |

## 四、强制流程

```
阶段 1（提案）：1/3 → 2/3
   写"方案"中至少 3 个备选方案 + 各自哲学锚

阶段 2（审阅）：2/3 → 3/3
   列出 falsifiable 命题 + 时间窗口
   列上游依赖
   列哲学锚

阶段 3（拍板）：3/3
   decided_by 必填人类标识符
   decided_at 必填日期
   决策不可改除非新决策覆盖
```
