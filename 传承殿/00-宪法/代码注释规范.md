# 代码注释规范

> **原语**：本项目沿用的创世叙事词汇，仅用于命名与溯源。
> **工程理解词语**：将原语翻译为可精确执行、可验证的工程术语；本文正文一律使用工程理解词语，原语仅在《术语对照表》中保留。
> 术语对照见 `传承殿/00-宪法/术语对照表.md`。

> **元治理**——代码注释是文档的延伸，必须有用高效，绝不垃圾。

## 一、核心原则

### 1.1 三不写

1. 不写 what（代码本身已说明做什么）
2. 不写显而易见（不写"这是一个函数"、"这里是循环"）
3. 不写 AI 味（不用"智能"、"优雅"、"高效"等无证据修辞）

### 1.2 三写

1. 写 why（为什么这么做：意图、约束、决策）
2. 写陷阱（易错的边界情况、非常规约定）
3. 写锚（关联设计稿/决策 ID，让代码可追溯）

## 二、5 种注释类型

### 类型 1：意图注释（函数/模块顶部）

用途：说明函数/模块的意图 + 决策锚 + falsifiable。

位置：函数/模块顶部 /// 或 //!。

长度：3-5 行（含决策锚）。

```rust
/// 化要求：项目负责人发布想法 → 决策者追问 → 化要求书
///
/// 决策锚：260826-2240 传承殿启动 + 260826-2210 4 分类抽象
/// falsifiable：追问通过率 > 60%（上线 3 个月）
fn 化要求(想法: &str) -> 要求书 { ... }
```

### 类型 2：约束注释（紧贴被约束代码）

用途：说明不能违反的规则。

位置：被约束代码的正上方 //。

长度：1 行。

```rust
// 约束：仅经档（永久档）可写（AGENTS 强制规则 § 边界）
记忆::写经档(内容, decided_by = "项目负责人");

// 约束：LLM 不调 LLM 生成内容（治理哲学追问引擎决策）
let 验证者 = 程序::新(LLM 池);
```

### 类型 3：陷阱注释（紧贴陷阱代码）

用途：说明易错的边界情况或非常规约定。

位置：陷阱代码的正上方 //。

长度：1-2 行。

```rust
// 陷阱：路径含中文时 Windows API 乱码，必须用 UTF-8 转 /
let 路径 = 路径.replace("\\", "/");

// 陷阱：rust 的 if let 在某些版本会触发 clippy 误报
#[allow(clippy::redundant_locals)]
let x = if let Some(v) = opt { v } else { 0 };
```

### 类型 4：决策锚注释

用途：代码关联的设计稿/决策。

位置：模块顶部或关键函数顶部。

长度：1-2 行。

```rust
//! 模块：RULE_REGISTRY
//! 决策锚：260826-2220 治理-司衡 § RULE_REGISTRY 单一真相源
//! 关联文档：02-概念/规则注册表/06-规则注册表.md
```

### 类型 5：TODO 注释

用途：已知未完成项。

位置：待办位置。

长度：1 行（含决策 ID 或截止日期）。

```rust
// TODO: 任务准入校验维度 5 步骤 5 待修正名单（260826-2230 工程-DSH）
// TODO: 自动巡检分级阈值（截止 2026-09-30）
```

## 三、注释禁区

| 禁写 | 反例 | 原因 |
|:--|:--|:--|
解释 what | 循环遍历数组 | 冗余 |
重复函数名 | 化要求函数 | 冗余 |
显而易见 | 这里初始化变量 | AI 味 |
修辞 | 智能调度 / 优雅实现 | 无证据 |
第一人称 | 我们决定用 X | 客观陈述原则 |
段落式长注释 | 第一段...第二段... | 必过期 |
复制设计稿 | 注释超过 5 行 | 文档双份维护 |
TODO 无截止 | TODO 以后改 | TODO 永不完成 |
借来的词 | 像乐高一样 | 命名纪律 |
注释掉的代码 | // old_fn(); | 用 git 历史 |

## 四、注释语言

### 4.1 默认中文

与项目代号"洪荒 · 世界"一致。

### 4.2 例外（保留英文）

- 业界缩写（LLM、PTC、DSL、API、IO）
- 库名（tokio::spawn, serde::Serialize）
- 错误信息（供搜索引擎检索）
- 标准库 trait 名称

### 4.3 标识符与注释分离

- 标识符：中文（白名单 SQLite/P0-P3/LLM 等标准词；Rust 工具链强制 ASCII 字段如 Cargo.toml key / src 文件名除外，按 AGENTS § 17）
- 注释：可中文可英文

## 五、注释模板

### 5.1 函数注释模板

```rust
/// <一句话意图>
///
/// 决策锚：<决策 ID>
/// falsifiable：<可证伪命题>
fn 函数名(...) -> ... { ... }
```

### 5.2 模块注释模板

```rust
//! 模块：<模块名>
//! 决策锚：<决策 ID>
//! 关联文档：<路径>
```

### 5.3 约束注释模板

```rust
// 约束：<具体规则>（<依据 ID>）
代码;
```

### 5.4 陷阱注释模板

```rust
// 陷阱：<具体陷阱>，必须 <解决方案>
代码;
```

## 六、注释维护

### 6.1 同步规则

- 代码改 → 注释立即改
- 设计稿改 → 决策锚 ID 立即改
- 过期注释立即删（不"注释掉"保留）

### 6.2 检查时机

| 时机 | 工具 | 命令 |
|:--|:--|:--|
commit 前 | cargo clippy | cargo clippy --workspace -- -D warnings |
Phase 末 | grep 过期 TODO | grep -r "TODO" --include="*.rs" . |
Phase 末 | grep 借来词 | grep -rE "乐高|智能|优雅" --include="*.rs" . |

### 6.3 过期注释处理

```bash
# 1. 找到过期注释
grep -n "// TODO" src/**/*.rs
# 2. 决策（已完成？删除；未完成？更新截止日期）
# 3. 删除或更新
```

## 七、对比示例

### 反例（AI 味 / 冗余）

```rust
/// 这个函数智能地初始化连接池，高效地处理并发
/// 我们精心设计了优雅的算法
fn 初始化() { ... }

// 循环遍历数组（冗余：for 已说明）
for i in array { /* 这里是循环 */ }

// 像乐高一样拼接插件（借来的词）
fn 拼接() { ... }
```

### 正例（有用高效）

```rust
/// 初始化连接池：连接数 = CPU 核数 × 2
///
/// 决策锚：260826-2240 传承殿启动 § 资源限制
/// falsifiable：连接池 100% 利用率 < 5s 启动
fn 初始化() -> 连接池 { ... }

// 约束：仅经档（永久档）可写（AGENTS 强制规则 § 边界）
记忆::写经档(内容, decided_by);

// 陷阱：路径含中文时 Windows API 乱码
let 路径 = 路径.replace("\\", "/");
```

## 八、引用与合规（防抄袭 / 防商标侵权）

### 8.1 引用规范（明确归因）

引用其他项目 / 标准 / 学术论文时**必须明确归因**：

```rust
// ✓ 正确：明确归因 + 决策锚
/// 接 DSH（DeepSeek Harness）的 Waterfall 事件设计哲学
///
/// 决策锚：02-概念/事件流/04-事件流.md § 三类事件
/// 参考文档：01-哲学/03-工程哲学.md
/// 引用方式：哲学借鉴（不复制代码）

// ✓ 正确：引用具体概念（不是大段复制）
/// Waterfall 模式：必须 next() 传递控制权（接 DSH § 2 模式）

// ✓ 正确：引用学术 / 标准
/// SHA-256 hash（FIPS 180-4 标准）

// ✗ 错误：模糊引用（无来源）
// 采用业界通用设计

// ✗ 错误：复制大段内容
// DSH 的 Waterfall 模式是这样实现的：
// ... 50 行复制 ...（这是抄袭，必须避免）

// ✗ 错误：暗示原作者与本项目有关联
// DSH 团队设计了这个方案
// （除非 DSH 团队确实是合作者，否则不能这样写）
```

### 8.2 引用三原则

1. **明确归因**：每个引用必须写"接 X / 参考 X / 借鉴 X"
2. **哲学借鉴 vs 代码复制**：
   - **哲学借鉴**（OK）：学习设计思路，独立实现
   - **代码复制**（NOT OK）：除非是 MIT/Apache 等明确允许的协议 + 标注原作者 + 协议
3. **引用合理**：单次引用不超过必要的最小篇幅（标准做法是 1-2 句话 + 文档指针）

### 8.3 商标与品牌名保护

| 类型 | 处理 | 示例 |
|:--|:--|:--|
| **作为引用来源提及** | ✓ 允许 | "接 DSH 设计哲学" "参考 sgmov/sihankor" |
| **作为方法/变量名** | ✗ 禁止 | fn dsh_init()（不要用别人的产品名做自己的 API 名） |
| **作为本项目品牌** | ✗ 禁止 | 不要起名 "DSH-Fork" 或类似 |
| **作为本项目商标** | ✗ 禁止 | 不要用别人的 logo 或商标 |

### 8.4 协议兼容

引入第三方依赖时**必须检查协议兼容**：

```
✓ 允许：
- MIT / Apache-2.0 / BSD（可商用、可修改、需保留版权声明）
- Public Domain / Unlicense

⚠ 警告：
- GPL / LGPL（强传染性，需评估）
- AGPL（网络服务也需开源）

✗ 禁止：
- 商业专有协议（未授权）
- SSPL（强传染）
- 自定义"禁止商用"协议

引入第三方 crate 时在注释中标注协议：
```rust
// 引入 serde = "1.0"（MIT/Apache-2.0 协议）
```

### 8.5 借鉴 vs 抄袭的判定标准

| 借鉴（OK） | 抄袭（NOT OK） |
|:--|:--|
| 学习设计哲学，独立实现 | 直接复制大段代码 |
| 提及来源 + 概念引用 | 无来源标注 |
| 1-2 句话点名 + 文档指针 | 50+ 行代码复制 |
| 哲学层概念（如 Waterfall） | 具体实现细节（如具体函数签名） |
| 标注 "接 X" / "参考 X" | 暗示"我们独立发明" |

### 8.6 商标与第三方引用清单

本项目可能引用的外部项目：
- **DSH**（DeepSeek Harness）：MIT 协议，工程参考
- **sgmov/sihankor**（司衡哲学仓库）：自行引用，哲学借鉴
- **Rust 标准库**：MIT/Apache-2.0
- 其他 crate：各自协议

引用时统一格式：
```rust
// 接 DSH 设计哲学（参考 01-哲学/03-工程哲学.md）
// 接治理工程哲学（参考 01-哲学/02-治理哲学.md）
```

### 8.7 注释中的"DSH"——具体示例

**问：注释中带 DSH 会被构成抄袭吗？**

**答：不会**。合理使用 / 引用他人工作 ≠ 抄袭。但需遵守：

```rust
// ✓ 推荐：明确归因 + 短引用
/// Waterfall 事件模式（接 DSH § 2 模式设计哲学）

// ✓ 推荐：引用具体概念 + 文档指针
/// 跨维事件总线：三类事件（Session/Agent/Capability）
/// 设计参考：01-哲学/03-工程哲学.md § 三类事件

// ⚠ 谨慎：长引用 + 不归因
// DSH 是这样实现的（接下来 30 行代码）……
// 这是 DSH 团队的原创设计，参考 DeepSeek 开源仓库。

// ✗ 禁止：复制 + 暗示原创
// Waterfall 模式（独创设计）：
// ... 50 行代码 ...（无 DSH 来源标注）
```

**判定关键**：
- ✓ 注明来源（"接 DSH" / "参考 DSH"）= 合理引用
- ✗ 复制 + 不标注 = 抄袭
- ✗ 复制 + 标注原作者 + 标注协议 = 合规（但仍需评估引用合理篇幅）

### 8.8 注释引用合规章程

每次 commit 前自查：

- [ ] 注释中所有外部引用都明确归因
- [ ] 没有无来源的大段复制
- [ ] 商标名 / 品牌名 只作为引用来源出现，不用作 API 名 / 变量名
- [ ] 第三方依赖在 Cargo.toml 中明确版本 + 协议标注
- [ ] 涉及外部实现的注释都附"接 X / 参考 X"标签
