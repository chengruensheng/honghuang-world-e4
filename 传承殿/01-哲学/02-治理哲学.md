## 一、6 柱石（架构根本 / 方法论原则 / 工程实现 / 检验 / 应变 / 元治理）

治理哲学（司衡工程哲学）把治理拆为 6 层（不是 4 层），多出来的两层是**应变**和**元治理**——这是本项目对 13 角色具象的修复方向。

## 二、5 工程基线（治理哲学核心）

### 基线 1：确定性程序是治理操作唯一执行者

> 「确定性程序是治理操作唯一执行者。LLM 只生成符号材料，不拥有写入知识包、事件流、意图锚定的权限。」

- **现状评估**：13 角色全 LLM 是结构性缺口
- **本项目承接**：4 分类抽象 + RULE_REGISTRY + decided_by 字段
- **可证伪**：上线 3 个月，关键决策（任务准入校验/验收驳回/最终裁决）的机械判定覆盖率 > 80%

### 基线 2：信息洪流是旧仓库失败根因

> 「人类注意力是稀缺资源，治理系统必须假设人类注意力是稀缺资源，将人类介入点限制在确定性程序无法自动处理的异常范围内。」

- **现状评估**：阶段 B 自动巡检 + 自动演化回路全开会产生大量 LLM 输出
- **本项目承接**：自动巡检分级（高/中/低） + 告警门 + 摘要生成
- **可证伪**：上线 3 个月，项目负责人每日介入次数 < 5 次

### 基线 3：人类只看异常

> 「人类只在告警时介入，不看原始日志。」

- **现状评估**：项目负责人直接看「对话」含原始 LLM 输出
- **本项目承接**：异常自动上报，正常流转事件流不打扰
- **可证伪**：上线 3 个月，异常告警准确率 > 90%

### 基线 4：可验证性约束

> 「操作来源可追溯、结果可机械校验、历史不可篡改。LLM 的不可复现输出不得作为治理决策的最终依据。」

- **现状评估**：事件流 + 回滚垫存在 + 哈希链已具备
- **本项目承接**：frozen outcome + 5 维评估机械化 + falsifiable
- **可证伪**：上线 1 个月，frozen outcome 校验 100% 通过

### 基线 5：治理延伸是减少 LLM 参与

> 「治理延伸是减少 LLM 参与，而非增加。」

- **现状评估**：13 角色全 LLM，只增不减
- **本项目承接**：4 分类抽象 + 关键决策确定化 + 多 LLM 投票仅关键决策
- **可证伪**：上线 6 个月，关键决策的 LLM 调用占比 < 20%

## 三、4 禁止条款

### 禁止 1：LLM 不可直改知识包

> 「禁止 LLM 直接修改知识包或意图锚定。」

- **承接**：decided_by 字段强制校验 + 4 分类的权限分层（决策者可写决策，但不可写知识包）
- **破戒后果**：写入失败 + 事件流记录 + 告警通知

### 禁止 2：不可复现的多 Agent 交互不可作治理决策依据

> 「禁止用不可复现的多 Agent 交互产出作为治理决策依据。」

- **承接**：关键决策多 LLM 投票 + 阈值（< 阈值升级决策者最终裁决）
- **破戒后果**：决策无效 + 强制走多 LLM 投票流程

### 禁止 3：治理操作必入事件流

> 「所有治理操作必须写入事件流，留痕不可篡改。」

- **承接**：frozen outcome + 哈希链 + 事件流强制契约
- **破戒后果**：操作拒收 + 异常告警

### 禁止 4：人类只通过异常摘要介入

> 「人类只通过异常摘要介入，不看原始日志。」

- **承接**：异常摘要 vs 原始对话分家 + 异常自动上报
- **破戒后果**：原始对话需明示进入才能看

## 四、5 法（尊重因果顺序 / 恰到好处 / 明确边界 / 定向调节 / 力度适配阶段）

### 尊重因果顺序：尊重因果方向

意图先于规范，规范先于实现。任何逆因果方向的操作都违背架构根本。

- **承接**：决策先于设计，设计先于实现
- **入稿点**：流水线（决策者→设计者→实现者→验收者）

### 恰到好处：收敛恰到好处

规约不多不少。过度规约=刻意有为；不足规约=放任发散。

- **承接**：RULE_COUNT 派生值 + 4 分类不增不减
- **入稿点**：规则注册表单一真相源

### 明确边界：知道不做什么

不是所有东西都需要规约。知道治理的边界比知道治理的方法更难。

- **承接**：CHARTER.md 非目标 + 8 概念边界
- **入稿点**：CHARTER.md § 非目标

### 定向调节：定向调节

损有余补不足。去冗余、减发散、填空白、补缺失。

- **承接**：自动巡检分级 + 异常自动上报 + 摘要生成
- **入稿点**：05-质量/ + 06-治理/

### 力度适配阶段：力度适配场景

治理有节奏：早期宽松保护探索，后期严格保护稳定。

- **承接**：阶段 A 关闭自动巡检（宽松），阶段 B 全开（严格）
- **入稿点**：ARCHITECTURE.md § 两阶段

### implements 取值空间（闭合）

决策契约的 `implements` 字段取单层哲学锚，合法值 = 6 柱石 ∪ 5 法：

- 6 柱石：`架构根本` `方法论原则` `工程实现` `检验` `应变` `元治理`
- 5 法：`尊重因果顺序` `恰到好处` `明确边界` `定向调节` `力度适配阶段`

格式：`implements: {柱石}` 或 `implements: {法名}`（单层，不用「柱石·自由词」两层）。

## 六、元三治（治理的治理）

> 「治理延伸是减少 LLM 参与」——这本身就要求治理自身也受治理约束。

### 核心规则修改需人类确认

核心规则修改需项目负责人确认（不绕过）。
- **承接**：13 条红线修改需新决策文档覆盖

### 分类不增不减

4 分类不增不减（不漂移）。
- **承接**：新增分类需 4 分类中至少 2 类 + 项目负责人拍板

### 核心逻辑不绕过检验

核心算法逻辑不绕过检验（驳回决策不绕过任务准入校验）。
- **承接**：验收者驳回强制走实现者重做，不允许决策者直接覆盖
