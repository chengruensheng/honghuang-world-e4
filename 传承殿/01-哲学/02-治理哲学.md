## 二、5 工程基线（司衡核心）

### 基线 1：确定程序是治理操作唯一执行者

> "确定性程序是治理操作唯一执行者。LLM 只生成符号材料，不拥有写入知识包、事件流、意图锚定的权限。"

- **现状评估**：13 角色全 LLM 是结构性缺口
- **传承殿承接**：4 分类抽象 + RULE_REGISTRY + decided_by 字段
- **可证伪**：上线 3 个月，关键决策（接单门/验收打回/终裁）的机械判定覆盖率 > 80%

### 基线 2：信息洪流是旧仓失败根因

> "人类注意力是稀缺资源，治理系统必须假设人类注意力是稀缺资源，将人类介入点限制在确定性程序无法自动处理的异常范围内。"

- **现状评估**：乙阶段巡世 + 进化环全开会产生大量 LLM 输出
- **传承殿承接**：巡世分级（高/中/低） + 告警门 + 摘要生成
- **可证伪**：上线 3 个月，界主每日介入次数 < 5 次

### 基线 3：人类只看异常

> "人类只在视图告警时介入，不看原始日志。"

- **现状评估**：界主直接看"对话"含原始 LLM 输出
- **传承殿承接**：异常门自动顶异常到界主视图，正常流转事件流不打扰
- **可证伪**：上线 3 个月，异常告警准确率 > 90%

### 基线 4：可验证性约束

> "操作来源可追溯、结果可机械校验、历史不可篡改。LLM 的不可复现输出不得作为治理决策的最终依据。"

- **现状评估**：事件流 + 回滚垫存在 + 哈希链已具备
- **传承殿承接**：frozen outcome + 5 维评估机械化 + falsifiable
- **可证伪**：上线 1 个月，frozen outcome 校验 100% 通过

### 基线 5：治理延伸是减少 LLM 参与

> "治理延伸是减少 LLM 参与，而非增加。"

- **现状评估**：13 角色全 LLM，只增不减
- **传承殿承接**：4 分类抽象 + 关键决策确定化 + 多 LLM 投票仅关键决策
- **可证伪**：上线 6 个月，关键决策的 LLM 调用占比 < 20%

## 三、4 禁止条款

### 禁止 1：LLM 不可直改知识包

> "禁止 LLM 直接修改知识包或意图锚定。"

- **承接**：decided_by 字段强制校验 + 4 分类的权限分层（道祖可写决策，但不可写知识包）
- **破戒后果**：写入失败 + 事件流记录 + 告警门通知

### 禁止 2：不可复现多 Agent 不可作治理决策

> "禁止用不可复现的多 Agent 交互产出作为治理决策依据。"

- **承接**：关键决策多 LLM 投票 + 阈值（< 阈值升级道祖终裁）
- **破戒后果**：决策无效 + 强制走多 LLM 投票流程

### 禁止 3：治理操作必入事件流

> "所有治理操作必须写入事件流，留痕不可篡改。"

- **承接**：frozen outcome + hash 链 + 事件流强制契约
- **破戒后果**：操作拒收 + 异常告警

### 禁止 4：人类只通过视图介入

> "人类只通过视图介入，不看原始日志。"

- **承接**：界主视图 vs 原始对话分家 + 异常门
- **破戒后果**：原始对话需明示进入才能看

## 四、5 法（顺因/有度/知止/损补/顺势）

### 顺因：尊重因果方向

意图先于规范，规范先于实现。任何逆因果方向的操作都是违道。

- **承接**：决策先于设计，设计先于实现
- **入稿点**：流水线（道祖→圣人→大罗→准圣）

### 有度：收敛恰到好处

规约不多不少。过度规约=刻意有为=违道；不足规约=放任发散=无收。

- **承接**：RULE_COUNT 派生值 + 4 分类不增不减
- **入稿点**：规则注册表单一真相源

### 知止：知道不做什么

不是所有东西都需要规约。知道治理的边界比知道治理的方法更难。

- **承接**：CHARTER.md 非目标 + 8 概念边界
- **入稿点**：CHARTER.md § 非目标

### 损补：定向调节

损有余补不足。去冗余、减发散、填空白、补缺失。

- **承接**：巡世分级 + 异常门自动顶 + 摘要生成
- **入稿点**：05-质量/ + 06-治理/

### 顺势：力度适配场景

治理有节奏：早期宽松保护探索，后期严格保护稳定。

- **承接**：甲阶段关闭巡世（宽松），乙阶段全开（严格）
- **入稿点**：ARCHITECTURE.md § 两阶段

## 五、元三治（治理的治理）

> "治理延伸是减少 LLM 参与"——这本身就要求治理自身也受治理约束。

### 治病

核心规则修改需界主确认（不绕过）。
- **承接**：13 红线修改需新决策文档覆盖

### 治益

4 分类不增不减（不漂移）。
- **承接**：新增分类需 4 分类中至少 2 类 + 界主拍板

### 治强

核心算法逻辑不绕过鉴（打回决策不绕过接单门）。
- **承接**：准圣打回强制走大罗重做，不允许道祖直接覆盖
