## 一、DSH 设计哲学

> "**没有特权的核心可供修改——你只需把插件挂到其他插件旁边来扩展**"

Agent Loop 本身都可被替换。这是 DSH 的核心断言，也是 传承殿的工程质量标杆。

### 三大原则

1. **核心无特权**：没有任何代码是"不可替换的"——核心可被插件替换
2. **插件可组合**：插件之间可以相互调用、覆盖、扩展
3. **事件可拦截**：每个关键节点都有 hook，插件可在 hook 处插入逻辑

### 与 传承殿的对应

| DSH 概念 | 传承殿落地 |
|:--|:--|
| 核心无特权 | 4 分类中每分类可替换为新 LLM 池 |
| 插件可组合 | 工具通过 manifest 拼装（不沿用命名） |
| 事件可拦截 | Waterfall 事件链（next() 模式） |

## 三、3 类事件（核心抽象）

### Session 事件（持久化）

append 到日志，broadcast 通过总线，需"事实穿越 reload"。
- **v3 落地**：frozen outcome + hash 链
- **入稿点**：02-概念/07-不可逆结果.md

### Agent 事件（agent/*）

携带 live Agent 对象，要观察或拦截 in-flight 工作时使用。
- **v3 落地**：4 分类的角色卡 + LLM 池
- **入稿点**：04-设计/模块设计/

### Capability 事件（fs/* / tools/* / telemetry/*）

attach policy 和 adapter 到某个接缝。
- **v3 落地**：工具 manifest + 权限枚举
- **入稿点**：02-概念/01-可插拔.md

## 四、2 种事件模式

### Waterfall 事件

必须 `next()` 把控制权传给下一个 listener。
- **典型场景**：`agent/pre-step`、`tools/pre-execute`
- **v3 落地**：每个工具调用前必须经过 Waterfall（不允许旁路）

### Serial 事件

独立拦截点，不调 `next()`。
- **典型场景**：`agent/turn-stopping`
- **v3 落地**：决策契约校验（decided_by 缺失则拒收）

## 五、Code Mode (PTC)

> "模型写一段 TypeScript 程序调用多个工具，`await tools.name(args)`，只把 `print` / `return` 内容送回模型。"

### 核心价值

原本 5 次 function calling 往返合并为 1 次代码块执行。
- **节省 token**：5 次往返每次都把前面所有 tool result 留在 history；PTC 只保留代码块 return
- **解耦**：把"工具调度"与"上下文占用"解耦
- **隔离**：模型生成的代码跑在独立 worker thread，环境空、heap cap、wall clock cap、硬终止

### 传承殿的考虑

- **复杂度**：Rust 实现需要独立进程隔离 + 资源 cap（tokio task + timeout）
- **价值**：节省 60-80% token（按 DSH 数据）
- **决策**：Phase 4 评估，不在 传承殿 立即实现

## 六、Step / Turn 概念

- **Step**：一次模型请求 + 它触发的工具调用
- **Turn**：零或多 step，从收到输入到全部完成

### Turn 生命周期（DSH 模式）

```
turn/start → claim 输入 → 组装 prompt + tool schemas → agent/pre-step waterfall
   → 消息 append → agent/request waterfall → llm/stream waterfall
   → assistant/message → tool/call → tools waterfall → tool/result
   → step/end → agent/turn-stopping → turn/end
```

### 传承殿落地

- 每个 Turn 必经 Waterfall 链
- 关键节点（step/end、turn/end）触发 falsifiable 记录
- tool/result 走 frozen outcome 校验

## 七、Profile × Bundle × Patch

### 三层正交组合

- **Profile**：用户/项目/场景的元数据
- **Bundle**：工具/插件包
- **Patch**：运行时补丁

### 传承殿的设想

- Profile：每个界主的偏好（决定 LLM 池选择）
- Bundle：工具集（如代码园 + 测试园）
- Patch：实验性功能（按 4 分类独立开关）

## 八、一键全验（10 项）

DSH 的工程质量标杆。传承殿必须实现 10 项门禁脚本：

1. `cargo fmt --check`（格式）
2. `cargo clippy --workspace -- -D warnings`（静态分析）
3. `cargo test --workspace --lib`（单元测试）
4. `cargo check --all-targets`（编译）
5. `cargo doc --no-deps`（文档）
6. `cargo audit`（安全审计）
7. `cargo deny check`（依赖审查）
8. 无 src/ 平铺目录（AGENTS § 10）
9. 无空目录
10. 无临时目录残留（AGENTS § 9）
