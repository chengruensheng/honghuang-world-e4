## 一、哲学层（为什么）

为什么需要 frozen outcome？因为**治理决策不能被篡改**。

- 决策可改 → 历史不可信 → 治理失效
- 决策不可改 → 历史可信 → 治理可验证

DSH 工程哲学：「frozen outcome」——工具结果只能追加不可改写。这是**工程层面对「治理动作必须可追溯」的实现**。

## 二、概念层（是什么）

### 3 个层面

1. **工具结果不可改**：工具调用结果一旦产出就不可改
2. **决策记录不可改**：决策者最终裁决一旦产出就不可改
3. **事件不可改**：事件流中任何事件都不可改（接 04-事件流.md）

### 三条铁律

1. **哈希校验**：每次产出计算哈希，哈希入事件流
2. **append-only**：只能追加，不能修改或删除
3. **违规即拒**：任何修改尝试都被拒绝并产生异常告警

## 三、工程层（怎么实现）

### 工具结果 frozen

```rust
pub struct 工具结果 {
    pub 工具ID: String,
    pub 输入: serde_json::Value,
    pub 输出: serde_json::Value,
    pub hash: Hash,           // sha256(输入 + 输出)
    pub decided_by: String,   // 工具调用者（可能是 LLM）
    pub 时间: Timestamp,
    pub immutable: bool,      // true = frozen
}

impl 工具结果 {
    pub fn 修改(&mut self, 新输出: serde_json::Value) -> Result<(), 错误> {
        if self.immutable {
            return Err(错误::不可改("工具结果已 frozen"));
        }
        // 不允许修改
    }
}
```

### 决策 frozen

```rust
pub fn 终裁(决策: &mut 终裁决策) -> Result<(), 错误> {
    if decision.已定档 {
        return Err(错误::不可改("终裁已定档"));
    }
    decision.已定档 = true;
    decision.hash = sha256(&decision);

}
```
