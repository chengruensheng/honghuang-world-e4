## 一、哲学层（为什么）

为什么需要流水线？因为**单角色承担全部职责会导致责任模糊**。

- 一人决策 + 设计 + 实现 + 验收 → 没有任何独立验证
- 角色分工 → 每层有自己的视角，能发现上一层遗漏的问题

治理哲学「检验·客观」 + DSH「Turn 生命周期」是同一个哲学断言：**多视角相互校验**比单视角自校验更可靠。

## 二、概念层（是什么）

### 4 阶段（接 01-哲学/01-世界观.md § 四、4 分类抽象）

```
决策者（决策） → 设计者（设计） → 实现者（实现） → 验收者（验收） → 决策者（最终裁决）
```

### 三条铁律

1. **不可跳层**：决策者不能直接验收，验收者不能直接设计
2. **不可反序**：实现者不能先于设计者设计
3. **可循环**：验收者驳回 → 实现者重做 → 验收者复验（最多 N 轮，超出升级决策者）

### 与「4 层神仙」命名的差异

| 「4 层神仙」命名 | 流水线概念 |
|:--|:--|
|「鸿钧/女娲/大罗/准圣」|「决策者/设计者/实现者/验收者」，剥掉神话角色名|
|「境界」|「职责」，可机械判定|
|「流程顺序」|「因果链」，单一方向|

### 循环控制

- `循环上限 = 3`（默认）
- 第 3 次仍驳回 → 自动升级决策者人工裁决
- 决策者裁决可强制通过（但需 falsifiable 记录）

### 事件链（接 DSH Waterfall）

每个阶段切换触发 Waterfall 事件：
- `agent/turn-start` → 化要求
- `agent/pre-step` → 设计评审
- `tools/pre-execute` → 实现校验
- `agent/turn-stopping` → 验收裁决
