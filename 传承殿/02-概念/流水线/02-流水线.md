# 02-流水线.md

> **概念·法**——不是"4 层神仙"，是"多角色分工比单角色更可靠"。

## 一、哲学层（为什么）

为什么需要流水线？因为**单角色承担全部职责会导致责任模糊**。

- 一人决策 + 设计 + 实现 + 验收 → 没有任何独立验证
- 角色分工 → 每层有自己的视角，能发现上一层遗漏的问题

司衡"鉴·客观" + DSH "Turn 生命周期" 是同一个哲学断言：**多视角相互校验**比单视角自校验更可靠。

## 二、概念层（是什么）

### 4 阶段（接 01-哲学/01-世界观.md § 四、4 分类抽象）

```
道祖级（决策） → 圣人级（设计） → 大罗金仙级（实现） → 准圣级（验收） → 道祖级（终裁）
```

### 三条铁律

1. **不可跳层**：道祖不能直接验收，准圣不能直接设计
2. **不可反序**：大罗不能先于圣人设计
3. **可循环**：准圣打回 → 大罗重做 → 准圣复验（最多 N 轮，超出升级道祖）

### 与"4 层神仙"命名的差异

| "4 层神仙" 命名 | 流水线概念 |
|:--|:--|
|"鸿钧/女娲/大罗/准圣"|"道祖/圣人/大罗金仙/准圣"，剥掉神话角色名|
|"境界"|"职责"，可机械判定|
|"流程顺序"|"因果链"，单一方向|

### 循环控制

- `循环上限 = 3`（默认）
- 第 3 次仍打回 → 自动升级道祖人工裁决
- 道祖裁决可强制通过（但需 falsifiable 记录）

### 事件链（接 DSH Waterfall）

每个阶段切换触发 Waterfall 事件：
- `agent/turn-start` → 化要求
- `agent/pre-step` → 设计评审
- `tools/pre-execute` → 实现校验
- `agent/turn-stopping` → 验收裁决
