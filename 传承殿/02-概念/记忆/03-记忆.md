## 一、哲学层（为什么）

为什么需要结构化记忆？因为**没有记忆就没有自我修正**。

- 短期记忆（session 内）— 工作记忆
- 中期记忆（session 间）— 经验沉淀
- 长期记忆（跨代际）— 文明延续

只靠短期记忆的系统**每次都从零开始**，无法积累经验。

## 二、概念层（是什么）

### 2.1 三层结构：门面 / 队长 / 兵（三问三答）

| 层 | 隐喻 | 回答的问题 | 语义 |
|:--|:--|:--|:--|
| 6 总纲 | 大队长 = 门面 | **能干什么** | 能力声明（Facade） |
| 36 格位 | 小队长 = 队长 | **我有什么** | 资产清单 |
| 块 | 士兵 | **有什么、有多少** | 具体数据 + 规模 |

访问顺序：**先问门面 → 再问队长 → 按需下探兵**，逐层 drill-down，LLM 按问题深度不越层。

- 门面层只写「能力声明」，不重复格位内容。
- 格位层全量常驻（36 格位拼接成一个上下文，每格位只填自己的本质）。
- 块层按需下探（数量/负重不一，目录树等巨物是兵不是队长）。

### 2.2 6 总纲（门面，三对内/外正交）

**6 总纲是永久固定的，不可新立、不可合并、不可废弃**：

| 总纲 | 能力声明 | 内/外 |
|:--|:--|:--|
| **内部** | 我是谁、我要做什么 | 内（AI 自己） |
| **外在** | 项目世界的结构/依赖/接口 | 外（整个项目） |
| **规则** | 外部约束/门禁/禁止 | 外（约束） |
| **执行** | 我怎么做（命令/技术栈） | 内（AI 行动） |
| **目标** | 我的方向（当前/未来） | 内（AI 方向） |
| **经历** | 我的历史（事件/教训） | 内（AI 历史） |

三对正交：**内↔外 / 规则↔执行 / 目标↔经历**。

**关键：内/外由 6 总纲决定，不由本质名决定。** 本质名本身不携带主体（实测：脱离总纲让 LLM 归内/外仅 24/36，带总纲前缀 36/36）。

### 2.3 36 本质（每总纲 6 专属，全局唯一，跨项目通用）

**36 格位 = 6 总纲 × 6 本质**，本质名全局唯一（每总纲 6 个专属本质，共 36 个不同的词）：

| 总纲（门面） | 6 本质（小队长） |
|:--|:--|
| 内部·我 | 角色 · 能力 · 职责 · 状态 · 记忆 · 边界 |
| 外在·项目 | 定位 · 结构 · 依赖 · 接口 · 环境 · 数据 |
| 规则·约束 | 禁止 · 门禁 · 规范 · 流程 · 例外 · 红线 |
| 执行·行动 | 命令 · 技术栈 · 步骤 · 工具 · 验证 · 产出 |
| 目标·方向 | 当前 · 未来 · 里程碑 · 验收 · 优先级 · 风险 |
| 经历·历史 | 事件 · 教训 · 决策 · 来源 · 时间 · 归档 |

**测试验证（D:\测试文件夹\载体\准确通用测试.py、修正测试.py）**：
- 唯一性：36 词全局唯一（代码检查无重复）。
- 内/外：由 6 总纲决定——带总纲前缀归内/外 36/36 全对，脱离总纲仅 24/36。
- 通用性：deepseek-harness 判「完整」无遗漏；洪荒传承殿提示缺失「版本/字符/层级/实例」，版本归定位或当前、字符归数据、层级归结构、实例属块层内容，修正后无实质遗漏。

**已知注意点（待项目负责人裁决，不擅自改名）**：本清单中「验收」「归档」与决策状态机（阶段）同名，「来源」「时间」与来源/时间维度语义同名。Rust 不同 enum 同名变体可共存（`本质::验收` / `阶段::验收`），用全限定路径区分；是否改名由项目负责人决定。

### 2.4 决策状态机（独立，6 阶段）

**6 阶段 = 提案 / 审阅 / 拍板 / 实施 / 验收 / 归档**，是决策的生命周期状态机，**独立于格位维度**（不是格位的第二维度）。

- 阶段是「这条内容走到哪了」（时间性），格位是「这是什么」（性质分类），两者正交。
- 阶段对应流水线：提案→审阅→拍板→实施→验收→归档，可循环驳回 ≤ 3 轮。

### 2.5 三层防护（防污染/防漂移/防遗忘）

| 层 | 防护 | 防什么 |
|:--|:--|:--|
| **第一层** | 按本质物理隔离（6 总纲 × 6 本质，编译期 enum） | 防跨本质污染 |
| **第二层** | 按格位细分（写入时强制总纲×本质归属匹配） | 防同总纲内漂移 |
| **第三层** | 永驻加载（启动时注入 36 行摘要） | 防被动遗忘 |

### 2.6 时间维度（经/权/行档）

| 档位 | 时间尺度 | 物理存储 | 写入权限 |
|:--|:--|:--|:--|
| **经档** | 永久（从不出错） | SQLite + 永久驻留 AI 上下文 | 项目负责人（永久）+ LLM（只追加建议） |
| **权档** | 当前 session | JSONL + hash 链 | LLM 可写（需 decided_by） |
| **行档** | session 内 | 内存 + 序列化 | LLM 可写 |

### 2.7 来源维度（3 源记录）

**代码 / LLM / 人类**——按"谁写的"分类。

来源可信度排序：**代码 > 人类 > LLM**（证据越硬越可信）。

### 2.8 四维正交

一条记忆条目 = **格位（总纲×本质，36） × 阶段（6） × 档位（3） × 来源（3）**。

- 例：`[外在/结构][拍板][经档][人类]` = 永久的、由人类拍板的项目结构
- 例：`[执行/命令][实施][权档][LLM]` = 当前 session 的、由 LLM 总结的执行命令
- 例：`[规则/门禁][拍板][经档][代码]` = 永久的、由代码生成的门禁

### 3.2 总纲 × 本质 归属校验（程序化，不让 LLM 自由判）

按"验证分离"原则：写入接口做校验，LLM 只生成内容——LLM 不能决定本质归属。

```rust
/// 总纲 × 本质 归属校验（本质必须属于该总纲的 6 个专属本质）
pub fn 本质归属(总纲: 总纲, 本质: 本质) -> bool {
    matches!(
        (总纲, 本质),
        (总纲::内部, 本质::角色 | 本质::能力 | 本质::职责 | 本质::状态 | 本质::记忆 | 本质::边界)
        | (总纲::外在, 本质::定位 | 本质::结构 | 本质::依赖 | 本质::接口 | 本质::环境 | 本质::数据)
        | (总纲::规则, 本质::禁止 | 本质::门禁 | 本质::规范 | 本质::流程 | 本质::例外 | 本质::红线)
        | (总纲::执行, 本质::命令 | 本质::技术栈 | 本质::步骤 | 本质::工具 | 本质::验证 | 本质::产出)
        | (总纲::目标, 本质::当前 | 本质::未来 | 本质::里程碑 | 本质::验收 | 本质::优先级 | 本质::风险)
        | (总纲::经历, 本质::事件 | 本质::教训 | 本质::决策 | 本质::来源 | 本质::时间 | 本质::归档)
    )
}

/// 写入校验：调用者必须显式指定总纲+本质，程序校验归属
pub fn 判定本质校验(内容: &str, 声称总纲: 总纲, 声称本质: 本质) -> 世界结果<()> {
    // 1. 归属校验：本质必须属于声称总纲
    if !本质归属(声称总纲, 声称本质) {
        return Err(错误::总纲本质不匹配(声称总纲, 声称本质));
    }
    // 2. 内容特征 × 声称总纲 的一致性（启发式）
    if !内容总纲一致(内容, 声称总纲) {
        return Err(错误::内容总纲不一致);
    }
    Ok(())
}

/// 内容总纲一致性（启发式：含某些关键词应归某总纲）
fn 内容总纲一致(内容: &str, 声称总纲: 总纲) -> bool {
    match 声称总纲 {
        总纲::内部 => 内容.contains("我是") || 内容.contains("身份") || 内容.contains("角色"),
        总纲::外在 => 内容.contains("结构") || 内容.contains("依赖") || 内容.contains("目录"),
        总纲::规则 => 内容.contains("必须") || 内容.contains("禁止") || 内容.contains("门禁"),
        总纲::执行 => 内容.contains("命令") || 内容.contains("构建") || 内容.contains("技术栈"),
        总纲::目标 => 内容.contains("目标") || 内容.contains("未来") || 内容.contains("阶段"),
        总纲::经历 => 内容.contains("已发生") || 内容.contains("历史") || 内容.contains("教训"),
    }
}
```

### 3.4 永驻摘要 + 全量加载 + 软放弃（三环）

```rust
/// 1. 永驻摘要：每个格位（总纲×本质）的经档条目压缩成 1 行
pub fn 永驻摘要() -> String {
    let mut 摘要 = String::new();
    for 总纲 in 所有总纲() {
        for 本质 in 总纲的所有本质() {
            if let Some(条目) = 查询经档(总纲, 本质) {
                if !条目.软放弃 {
                    摘要.push_str(&format!("{}：{}
", 格位坐标(总纲, 本质), 条目.摘要));
                }
            }
        }
    }
    摘要  // 共 36 行
}

/// 2. 全量加载：把 36 行摘要加载到 AI 上下文
pub fn 启动时加载(上下文: &mut AI上下文) {
    上下文.注入(永驻摘要());
    // AI 每次启动都看这 36 行——"永远记得"
}

/// 3. 软放弃：AI 显式声明放弃某个永驻条目
pub fn 软放弃(id: 记忆ID, decided_by: &str, 理由: String) -> 世界结果<()> {
    if decided_by.is_empty() {
        return Err(错误::缺失决策者);
    }
    标记软放弃(id, decided_by, 理由);
    Ok(())
}
```
