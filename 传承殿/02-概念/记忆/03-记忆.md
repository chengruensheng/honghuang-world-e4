# 03-记忆.md

> **概念·法**——36 格位 = 6 范畴 × 6 阶段 的三维正交模型 + 三层防护。

## 一、哲学层（为什么）

为什么需要结构化记忆？因为**没有记忆就没有自我修正**。

- 短期记忆（session 内）— 工作记忆
- 中期记忆（session 间）— 经验沉淀
- 长期记忆（跨代际）— 文明延续

只靠短期记忆的系统**每次都从零开始**，无法积累经验。

## 二、概念层（是什么）

### 2.1 36 格位为底 + 可细分（派生关系）

**36 是派生值**，不是硬编码：

格位总数 = 范畴数 × 阶段数 = 6 × 6 = 36

#### 2.1.1 永久固定的 6 范畴

**6 范畴是永久固定的，不可新立、不可合并、不可废弃**（元·治·治益）：
- **目标** Goal — 我们要到哪里去
- **规则** Rule — 必须遵守的约束
- **自我** Self — 我们是谁
- **程序** Process — 怎么做
- **世界** World — 外部状态
- **经历** Experience — 已经发生的事

减少一个会有本质无处安放；增加一个会冗余。

#### 2.1.2 永久固定的 36 格位

**36 格位 = 6 范畴 × 6 阶段**，全部固定（永不新立、不可合并）：

- 6 阶段（每个本质都经过）：**提案 / 审阅 / 拍板 / 实施 / 验收 / 归档**

#### 2.1.3 格位下可细分（继承父 + 更加具体，暂不限数）

**每个 36 格位下面还能细分**，按需扩展：

- 细分原则：
  - **继承父特性**：子格位自动继承父格位的"本质 + 阶段"属性
  - **更加具体**：子格位比父格位更细化、更具体
  - **暂不限数**：细分数量由界主/AI 按需决定

- 示例：
  - `目标/拍板/传承殿`（项目名 = `目标/拍板` 的具体实例）
  - `目标/拍板/9根维度`（世界观 = `目标/拍板` 的具体设计）
  - `目标/拍板/6层结构`（架构 = `目标/拍板` 的具体设计）
  - `规则/拍板/AI不直改`（司衡禁止 1 = `规则/拍板` 的具体规则）
  - `规则/拍板/decided_by必填`（决策契约 = `规则/拍板` 的具体规则）
  - `程序/实施/Cargo工作空间`（实施细节 = `程序/实施` 的具体）

- 路径表示：`范畴/阶段/细分名`（斜杠分隔，类似文件系统路径）
- 父格位可独立存在（不强制有子格位）
- 子格位可继续分（`目标/拍板/传承殿/v3`）

#### 6 范畴（范畴维度）

- **目标** Goal — 我们要到哪里去（未来方向）
- **规则** Rule — 必须遵守的约束（不变律）
- **自我** Self — 我们是谁（身份 + 边界）
- **程序** Process — 怎么做（方法 + 工具）
- **世界** World — 外部状态（环境 + 数据）
- **经历** Experience — 已经发生的事（历史）

#### 6 阶段（阶段维度，每个本质都经过）

- **提案** Proposal — 1/3 决策的初始
- **审阅** Review — 2/3 决策的审议
- **拍板** Decision — 3/3 决策的拍定
- **实施** Implementation — 执行的开始
- **验收** Validation — 验证完成
- **归档** Archive — 永久保存

### 2.2 三层防护（防污染/防漂移/防遗忘）

| 层 | 防护 | 防什么 |
|:--|:--|:--|
| **第一层** | 按本质物理隔离 | 防跨本质污染（代码≠背景） |
| **第二层** | 按格位细分（同本质 6 阶段） | 防同本质内漂移 |
| **第三层** | 永驻加载（每次全量注入） | 防被动遗忘 |

#### 第一层：按本质物理隔离（防污染）

不同本质用不同类型（编译期隔离）：

```rust
pub struct 目标条目(pub 记忆条目);
pub struct 规则条目(pub 记忆条目);
pub struct 自我条目(pub 记忆条目);
pub struct 程序条目(pub 记忆条目);
pub struct 世界条目(pub 记忆条目);
pub struct 经历条目(pub 记忆条目);

// 不同本质的验证逻辑独立
impl 目标条目 { pub fn 验证目标(&self) -> 世界 { ... } }
impl 规则条目 { pub fn 验证规则(&self) -> 世界 { ... } }
```

#### 第二层：按格位细分（防漂移）

36 个细颗粒格位，每个都有唯一名称。写入时强制 enum 匹配（不允许字符串漂移）：

```rust
/// 写入函数：强制 4 维正交（不允许 LLM 推断）
pub fn 写入(范畴: 范畴, 阶段: 阶段, 内容: String) -> 世界结果<记忆ID> {
    // 编译期检查：4 个参数都是 enum，不可能是字符串
    // LLM 调此函数时，必须显式指定范畴和阶段
    // 不允许自由判定
    let 档位 = 判定档位(范畴, 阶段);
    let 来源 = 判定来源(范畴, 阶段);
    // ... 写入
}
```

#### 第三层：永驻加载（防遗忘）

经档（永驻档）= 永久驻留 AI 上下文窗口：

```rust
/// 启动时加载所有经档条目到 AI 上下文
pub fn 加载永驻() -> Vec<记忆条目> {
    读取经档全部()
}

/// 永驻摘要：每个范畴 + 阶段的经档条目压缩成 1 行
/// 例：
/// 目标/拍板：传承殿 = 9 根 + 6 层 + 4 分类
/// 规则/拍板：AI 不直改知识包（司衡禁止 1）
/// ... 共 36 行摘要
pub fn 永驻摘要() -> String {
    let mut 摘要 = String::new();
    for 范畴 in 所有范畴() {
        for 阶段 in 所有阶段() {
            let 条目 = 查询经档(范畴, 阶段);
            摘要.push_str(&format!("{}：{}
", 范畴_阶段(范畴, 阶段), 条目.摘要));
        }
    }
    摘要
}

/// 全量加载：把 36 行摘要加载到 AI 上下文
/// AI 每次启动都看这 36 行——"永远记得"
pub fn 启动时加载(上下文: &mut AI上下文) {
    上下文.注入(永驻摘要());
}

/// 软放弃：AI 显式声明放弃某个永驻条目
/// 但需要 decided_by + falsifiable
pub fn 软放弃(id: 记忆ID, decided_by: &str, 理由: String) -> 世界结果<()> {
    if decided_by.is_empty() {
        return Err(错误::缺失决策者);
    }
    // 软放弃不等于删除，只是标记"暂时不看"
    // 后续可恢复
    写入软放弃标记(id, decided_by, 理由);
    Ok(())
}
```

### 2.3 维度 2：时间维度（3 档投影）

**经档 / 权档 / 行档**——按"怎么用"分类。

| 档位 | 时间尺度 | 物理存储 | 写入权限 |
|:--|:--|:--|:--|
| **经档** | 永久（从不出错） | SQLite + 永久驻留 AI 上下文 | 界主（经）+ LLM（只追加建议） |
| **权档** | 当前 session | JSONL + hash 链 | LLM 可写（需 decided_by） |
| **行档** | session 内 | 内存 + 序列化 | LLM 可写 |

### 2.4 维度 3：来源维度（3 源记录）

**代码 / LLM / 人类**——按"谁写的"分类。

来源可信度排序：**代码 > 人类 > LLM**（证据越硬越可信）。

### 2.5 三维正交的实际工作

- 一条记忆条目 = 一个格位（6 范畴 × 6 阶段 = 36 格位折叠轴）+ 一个时间档 + 一个来源
- 例：`[目标/拍板][经档][人类]` = 永久的、由人类拍板的目标
- 例：`[程序/实施][权档][LLM]` = 当前 session 的、由 LLM 总结的实施细节
- 例：`[规则/拍板][经档][代码]` = 永久的、由代码生成的规则（lint 自动生成）

### 3.2 范畴判定的程序化规则（不让 LLM 自由判）

按"验证分离"原则：写入接口（程序）做校验，LLM 只生成内容——LLM 不能决定本质。

```rust
/// 范畴判定（程序化规则）
pub fn 判定本质校验(
    内容: &str,
    声称本质: 范畴,
    声称阶段: 阶段,
) -> 世界结果<()> {
    // 1. 调用者必须显式指定范畴（程序不帮 LLM 判定）
    // 2. 程序按规则校验"这是不是合理"
    // 3. 模糊情况：返回错误 + 提示追问，不自动判

    // 规则：本质 × 阶段 的合法性
    if !本质阶段合法性(声称本质, 声称阶段) {
        return Err(错误::本质阶段不匹配(声称本质, 声称阶段));
    }

    // 规则：内容特征 × 声称本质 的一致性（启发式）
    if !内容本质一致(内容, 声称本质) {
        return Err(错误::内容本质不一致);
    }

    Ok(())
}

/// 内容本质一致性（启发式：含某些关键词应归某本质）
fn 内容本质一致(内容: &str, 声称本质: 范畴) -> bool {
    match 声称本质 {
        目标 => 内容.contains("TODO") || 内容.contains("计划") || 内容.contains("未来"),
        规则 => 内容.contains("必须") || 内容.contains("禁止") || 内容.contains("约束"),
        自我 => 内容.contains("我是") || 内容.contains("身份") || 内容.contains("角色"),
        程序 => 内容.contains("代码") || 内容.contains("函数") || 内容.contains("实现"),
        世界 => 内容.contains("环境") || 内容.contains("状态") || 内容.contains("系统"),
        经历 => 内容.contains("已发生") || 内容.contains("历史") || 内容.contains("过去"),
    }
}

/// 本质 × 阶段合法性（启发式）
fn 本质阶段合法性(本质: 范畴, 阶段: 阶段) -> bool {
    match 本质 {
        目标 => matches!(阶段, 提案 | 拍板 | 实施),  // 目标不能"归档"
        规则 => matches!(阶段, 提案 | 审阅 | 拍板),  // 规则不能"实施"
        自我 => matches!(阶段, 提案 | 拍板),         // 自我很少变更
        程序 => matches!(阶段, 提案 | 审阅 | 实施 | 验收),  // 程序常实施
        世界 => matches!(阶段, 提案 | 验收),         // 世界是外部状态
        经历 => matches!(阶段, 提案 | 实施 | 验收 | 归档),  // 经历可归档
    }
}
```

impl 记忆写入 for 记忆承载 {

    }
