> **概念·方法论原则**——不是「grilling engine」，是「治理上游要先收敛意图」。

## 一、哲学层（为什么）

为什么需要追问？因为**没有意图收敛就没有治理**。

- 模糊意图 → LLM 自由发挥 → 结果不可预测
- 收敛意图 → LLM 在边界内工作 → 结果可验证

治理哲学追问引擎的哲学：**治理的起点是让用户明确自己的意图**。LLM 不能替你做这个决定。

## 二、概念层（是什么）

### 4 问题（代码枚举 `追问::道二 / 顺因 / 有度 / 知止`，属结构专名）

```
道二（意图确认） → 你的目标是什么？
顺因（依赖确认） → 依赖什么？上下文关系？
有度（边界确认） → 边界 / 约束是什么？
知止（终止条件） → 何时停止？
```

### 与「grilling engine」命名的差异

| 「grilling engine」命名 | 追问概念 |
|:--|:--|
|「engine」|「机制」，engine 暗示自动，机制更准确|
|「grilling」|「追问」，是元层而非数据层|
|「自调 LLM」|「生成提示词」，不调 LLM 生成内容|

### 三条铁律

1. **不调 LLM 生成内容**——治理哲学「不生成只验证」原则
2. **生成提示词而非答案**——决定权在项目负责人
3. **4 问题一次性追问**——不允许轮询（Solo 模式）
