# 08-验证分离.md

> **概念·法**——"验证者与生成者必须分离"。

## 一、哲学层（为什么）

为什么 LLM 不能直改知识包？因为**自我验证没有公信力**。

- LLM 生成 + LLM 验证 → 验证者被生成者污染
- LLM 生成 + 程序验证 → 验证客观可证伪
- LLM 生成 + 人类验证 → 验证权威可追溯

司衡追问引擎决策原文："追问引擎持有 API key，自己调 LLM 生成内容——违反核心定位：司衡不生成代码/文档，只验证。而且验证者与生成者做在同一进程内，鉴的公信力减弱。"

## 二、概念层（是什么）

### 写入权限分层

| 写入对象 | LLM 可写？ | 校验方式 |
|:--|:--|:--|
| **记忆条目**（经档） | ❌ | 界主（经）+ decided_by |
| **记忆条目**（权档） | ⚠️ 仅建议 | decided_by 强制 |
| **事件流** | ❌ | 程序生成 + hash 链 |
| **决策契约** | ❌ | 人类标识符必填 |
| **工具结果** | ⚠️ 仅生成 | frozen outcome |
| **代码** | ⚠️ 大罗金仙级 | 经流水线 + 验收 |

### 三条铁律

1. **LLM 是生成者**：只能生成符号材料（提示词、代码、初稿）
2. **程序是验证者**：可机械判定的部分必须程序验证
3. **人类是终极验证**：重大决策由界主拍板（decided_by）

## 三、工程层（怎么实现）

### 写入接口

```rust
pub trait 可写 {
    fn 写入(&mut self, 内容: serde_json::Value, decided_by: &str) -> Result<(), 错误>;
}

// LLM 写入需要 decided_by
impl 可写 for 记忆条目 {
    fn 写入(&mut self, 内容: serde_json::Value, decided_by: &str) -> Result<(), 错误> {
        if decided_by.is_empty() {
            return Err(错误::缺失决策者);
        }
        self.内容 = 内容;
        self.decided_by = decided_by.to_string();
        Ok(())
    }
}
```

### 校验流程

1. LLM 调用写入接口
2. 校验 decided_by 字段
3. 校验写入权限（4 分类的权限分层）
4. 校验完成后落盘 + 事件流记录

### 违规检测

- decided_by 缺失 → 写入失败 + 异常告警
- LLM 直写知识包 → 触发 4 分类权限校验 + 拒绝
- LLM 修改已 frozen 内容 → 触发 frozen outcome 校验 + 拒绝
