# 角色抽象 4 分类

> **原语**：本项目沿用的创世叙事词汇，仅用于命名与溯源。
> **工程理解词语**：将原语翻译为可精确执行、可验证的工程术语；本文正文一律使用工程理解词语，原语仅在《术语对照表》中保留。
> 术语对照见 `传承殿/00-宪法/术语对照表.md`。
> 说明：`道祖级 / 圣人级 / 准圣级 / 大罗金仙级` 是代码枚举变体（结构专名），工程语义为「决策者 / 设计者 / 验收者 / 实现者」，代码中按原字引用。

## 背景

司衡基线 1：**确定性程序是治理操作唯一执行者**。

具象角色（如命名角色）依赖 LLM 扮演——无法机械判定，无法验证。

抽象分类按「职责」分层——可以机械判定（权限 + 工具 + 路径前缀）。

## 方案

**方案 A（采纳）：4 分类抽象**

| 分类 | 职责 | LLM 角色 | 机械判定 |
|:--|:--|:--|:--|
| **决策者** | 化要求 / 派遣 / 最终裁决 / 定档 | 主决策 | 权限枚举 + 多 LLM 投票 |
| **设计者** | 设计 / 评审 | 主设计 | 写权限=假 + 评审四元组 |
| **验收者** | 验收（六维：前 4 维机械 + 后 2 维 LLM） | 主验收 | 6 维中 4 维可机械测试 |
| **实现者** | 实现（按领域分工） | 主执行 | 写权限=真 + 路径前缀校验 |

**方案 B（不采纳）：命名角色扮演**
- 不采纳理由：依赖 LLM 扮演，无法机械判定

**方案 C（不采纳）：完全去 LLM 角色**
- 不采纳理由：抽象分类仍需要 LLM 生成内容（语义层），只是不让 LLM 担任决策位

## 后果

**正面后果**：
- 4 张角色卡，每张带 falsifiable 条件
- 行为判定机械化
- 多 LLM 投票仅作用于关键决策

**代价与风险**：
- LLM 池策略需重新设计
- 角色偏好表需重写

## 可证伪条件验证

每 1 个月盘点一次：
- 4 分类机械判定覆盖率
- 流水线跳层次数
- 职责重叠检查
