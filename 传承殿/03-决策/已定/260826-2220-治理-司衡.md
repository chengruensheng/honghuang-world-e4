# 治理哲学承接司衡 5 基线 + 4 禁止


## 背景

司衡工程哲学（sgmov/sihankor）定义了 5 工程基线 + 4 禁止条款 + 5 法 + 元三治。

这是治理哲学的**外部锚定**——传承殿不自创治理哲学，而是承接司衡。

## 方案

**方案 A（采纳）：全面承接**
- 5 工程基线全部入 AGENTS.md § A
- 4 禁止条款全部入 AGENTS.md § B
- 5 法（顺因/有度/知止/损补/顺势）作为决策依据
- 元三治（治病/治益/治强）作为治理的治理
- 追问引擎 4 问题（道二/顺因/有度/知止）入道祖入口

**方案 B（不采纳）：仅承接部分**
- 不采纳理由：未根本解决 LLM 决策权过重问题

**方案 C（不采纳）：完全照搬司衡**
- 不采纳理由：司衡是 Rust 单机 CLI 工具，传承殿是分布式协作系统，需适配

### 承接机制

| 司衡基线 | 传承殿承接 |
|:--|:--|
| 基线 1：确定程序是治理操作唯一执行者 | 4 分类抽象 + RULE_REGISTRY + decided_by |
| 基线 2：信息洪流是旧仓失败根因 | 巡世分级 + 告警门 + 摘要生成 |
| 基线 3：人类只看异常 | 异常门自动顶异常 |
| 基线 4：可验证性约束 | frozen outcome + hash 链 + falsifiable |
| 基线 5：治理延伸是减少 LLM 参与 | 关键决策确定化 + 多 LLM 投票 |

## 后果

**正面后果**：
- 治理动作可追溯 + 可证伪 + 可机械判定
- LLM 不再担任决策位
- 决策有 falsifiable 条件 + 时间窗口

**代价与风险**：
- 关键决策的 LLM 调用占比下降（短期性能影响）
- 多 LLM 投票增加 token 消耗
- 异常门 + 摘要生成需要新增模块
