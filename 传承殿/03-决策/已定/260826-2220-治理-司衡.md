# 治理哲学承接司衡 5 基线 + 4 禁止

> **原语**：本项目沿用的创世叙事词汇，仅用于命名与溯源。
> **工程理解词语**：将原语翻译为可精确执行、可验证的工程术语；本文正文一律使用工程理解词语，原语仅在《术语对照表》中保留。
> 术语对照见 `传承殿/00-宪法/术语对照表.md`。
> 说明：五法（尊重因果顺序/恰到好处/明确边界/定向调节/力度适配阶段）与元三治（核心规则修改需人类确认/分类不增不减/核心逻辑不绕过检验）的对应原语见《术语对照表》。

## 背景

司衡工程哲学（sgmov/sihankor）定义了 5 工程基线 + 4 禁止条款 + 5 法 + 元三治。

这是治理哲学的外部锚定——传承殿不自创治理哲学，而是承接司衡。

## 方案

**方案 A（采纳）：全面承接**
- 5 工程基线全部入 AGENTS.md § A
- 4 禁止条款全部入 AGENTS.md § B
- 5 法（尊重因果顺序/恰到好处/明确边界/定向调节/力度适配阶段）作为决策依据
- 元三治（核心规则修改需人类确认/分类不增不减/核心逻辑不绕过检验）作为治理的治理
- 追问引擎 4 问题（意图确认/尊重因果顺序/恰到好处/明确边界）入决策者入口

**方案 B（不采纳）：仅承接部分**
- 不采纳理由：未根本解决 LLM 决策权过重问题

**方案 C（不采纳）：完全照搬司衡**
- 不采纳理由：司衡是 Rust 单机 CLI 工具，传承殿是分布式协作系统，需适配

### 承接机制

| 司衡基线 | 传承殿承接 |
|:--|:--|
| 基线 1：确定性程序是治理操作唯一执行者 | 4 分类抽象 + RULE_REGISTRY + decided_by |
| 基线 2：信息洪流是旧仓失败根因 | 巡检分级 + 告警上报 + 摘要生成 |
| 基线 3：人类只看异常 | 异常自动上报 |
| 基线 4：可验证性约束 | frozen outcome + hash 链 + falsifiable |
| 基线 5：治理延伸是减少 LLM 参与 | 关键决策确定化 + 多 LLM 投票 |

## 后果

**正面后果**：
- 治理动作可追溯 + 可证伪 + 可机械判定
- LLM 不再担任决策位
- 决策有 falsifiable 条件 + 时间窗口

**代价与风险**：
- 关键决策的 LLM 调用占比下降（短期性能影响）
- 多 LLM 投票增加 token 消耗
- 异常上报 + 摘要生成需要新增模块
