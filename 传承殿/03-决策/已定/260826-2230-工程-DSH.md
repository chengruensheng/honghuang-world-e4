# 工程标准对齐 DSH


## 背景

DeepSeek Harness（DSH）定义了 6 子系统 + 3 类事件 + 2 模式 + 一键全验。

这是工程质量标准的**外部锚定**——传承殿不自创工程标准，而是对齐 DSH。

## 方案

**方案 A（采纳）：全面对齐 DSH**
- 6 子系统作为架构骨架（session/system-prompt/tools/agent/agent-loop/scope）
- 3 类事件（Session/Agent/Capability）+ 2 模式（Waterfall/Serial）
- frozen outcome + hash 链
- 一键全验 10 项
- Code Mode (PTC) 评估（Phase 4）

**方案 B（不采纳）：仅借鉴部分**
- 不采纳理由：未根本解决工程质量标准化问题

**方案 C（不采纳）：照搬 DSH TypeScript 技术栈**
- 不采纳理由：失去 Rust 类型系统 + 中文标识符

### 工程标准清单

| DSH 标准 | 传承殿承接 |
|:--|:--|
| 万物皆插件 | Service Definition + 插件注册表 |
| Waterfall 事件 | next() 链 + 拦截点 |
| 三类事件 | Session/Agent/Capability |
| frozen outcome | hash 校验 + append-only |
| 一键全验 | 10 项门禁脚本 |
| Profile × Bundle × Patch | 用户偏好 + 工具集 + 实验功能 |

## 后果

**正面后果**：
- 工程质量可量化（10 项门禁）
- 插件可独立替换
- 事件可追溯 + 不可篡改

**代价与风险**：
- 事件流需重构（Waterfall + Serial 模式）
- frozen outcome 需新增 hash 校验层
- 工具 manifest 字段扩展
