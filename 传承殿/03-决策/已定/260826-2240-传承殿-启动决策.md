# 传承殿项目从零启动


## 背景

传统 AI 协作的常见陷阱：
1. **借来的词**——把外部概念（如"乐高"、"工具 manifest"）当现有命名空间直接用
2. **未推导的命名**——每个命名必须先回答"为什么叫这个"
3. **决策无据**——缺乏 decided_by + falsifiable 契约，无法验证

哲学先于代码。从零开始：
- 30 天哲学推导（每个概念哲学层 + 概念层 + 工程层）
- 然后再落码（避免被已有命名污染）

## 方案

**方案 A（采纳）：从零启动传承殿**

- 位置：E:\洪荒 - 世界\传承殿\
- 文档结构：8 大类（00-宪法 / 01-哲学 / 02-概念 / 03-决策 / 04-设计 / 05-质量 / 06-治理 / 08-参考）
- 哲学推导优先：每个概念哲学 → 概念 → 工程 三层
- 决策契约：每决策 decided_by + falsifiable + implements
- 不沿用未推导的命名

**方案 B（不采纳）：沿用已有命名**
- 不采纳理由：未根本解决"借来的词"问题

**方案 C（不采纳）：照搬外部技术栈**
- 不采纳理由：失去中文标识符 + Rust 类型系统

## 后果

**正面后果**：
- 30 天交付一个"哲学先于代码"的文档基础
- 决策可追溯 + 可证伪 + 可机械判定
- 摆脱任何"借来的词"污染

**代价与风险**：
- 文档撰写时间（30 天）
- 部分核心概念需要重新推导
- 团队学习成本

## 可证伪条件验证

每 3 个月盘点一次：
- 位置是否在 传承殿/ 下
- 是否新出现未推导的命名
- 每份文档是否带三件套
