## 背景

v1.0.0 release 后，22 个 crate 均为平铺 `入口.rs` 单文件结构，目录命名用纯连字符（`基础设施-域`）。
对照 `00-宪法/开发遵守格式模板.md § 1.3` 与 `§ 3.1`：

- § 1.3 要求域 = `XX - 域`、府 = `XX - 府`（空格两侧连字符）
- § 3.1 要求府内 = `入口.rs + Y-殿/ + Z-阁/ + W-园/` 嵌套

当前结构两项均不满足。本次重构使代码结构符合 D 盘模板，不改变任何对外行为。

## 方案

### 主方案：分两步

**第一步·目录命名合规**（全局，一次性）
- `基础设施-域` → `基础设施 - 域`
- `插件上下文-府` → `插件上下文 - 府`
- 同步更新 workspace Cargo.toml members + 各 crate Cargo.toml [lib] path
- 验证 cargo check + test

**第二步·殿阁园深化**（逐 crate，可并行）
- 仅对 > 200 行的 crate 拆分（12 个大 crate）
- 小 crate（< 200 行，9 个）保持平铺（符合"简化 > 复杂"）
- 每个 crate：入口.rs 保留 pub mod + pub use，实现下沉到殿/阁/园
- 非 ASCII 模块名用 `#[path]` 桥接

### 备选方案 A：全部 22 crate 都拆殿阁园
- 不采纳：9 个小 crate（< 200 行）拆分后每层只有 1-2 个小文件，违反"拒绝单链"反而增加认知负担

### 备选方案 B：只改目录命名不拆殿阁园
- 不采纳：D 盘模板 § 3.1 明确要求府内嵌套，且大 crate（1379 行记忆承载）平铺已影响可读性

## 后果

### 正面
- 目录命名符合 D 盘模板，新协作者可一键复制格式
- 大 crate 逻辑分殿/阁/园，可读性提升
- 为未来园级实现替换（可插拔）做好结构准备

### 代价与风险
- 风险 1：非 ASCII 模块名 `#[path]` 桥接写法错误导致编译失败 → 每 crate 拆完立即 cargo check
- 风险 2：拆分时 pub use 导出遗漏导致下游 crate 编译失败 → 拆完跑 workspace test
- 风险 3：目录重命名破坏 git 历史 → 用 `git mv` 保留 rename 检测
- 代价：22 crate × 重构工作量，约 1 个工作日

## 可证伪条件验证

- 重构完成后立即跑一键全验，11/11 全绿即第一步通过
- grep 检查域/府目录命名，全部含 ` - ` 即第二步通过
- cargo test --workspace 205 测试全过即行为不变
