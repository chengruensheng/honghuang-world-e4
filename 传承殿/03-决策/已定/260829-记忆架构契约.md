# 260829-记忆架构契约：格位记忆双工流水线

> **决策者**：项目负责人（AI 自主落地，未经人类最终验收授权，项目负责人日后确认可授权）
> **决策锚**：工程实现·格位记忆落地契约（前端执行/后端整理双工流水线）
> **关联文档**：传承殿/02-概念/记忆/03-记忆.md
> **可证伪条件**：交付不阻塞、债务对账、必填字段必填、人类最终验收授权优先
> **入稿日期**：2026-08-29

## 一、决策内容

本契约定义「格位记忆」的完整读写生命周期与前后端双工流水线。核心结论一句话：

> **不保留对话历史上下文条；一切回填 36 格位；块每格位默认取最新、按需召回历史；前端执行与后端整理双 worker 并发，前端 fire-and-forget 交付后立即进下一任务，永不阻塞后端。**

## 二、格位模型：36 是本体，总纲是定位轴（对齐四维正交记忆模型）

- **36 格位 = 本体**（6 总纲 × 6 本质），承载所有记忆内容，全量常驻（实测 1311 token）。
- **总纲（6 个：内部/外在/规则/执行/目标/经历）= 纯定位轴**，仅回答「现在在第几卷」，不承载实质内容、不占额外 token。
- **本质（36 词，每总纲 6 专属）**：内部（角色/能力/职责/状态/记忆/边界）、外在（定位/结构/依赖/接口/环境/数据）、规则（禁止/门禁/规范/流程/例外/红线）、执行（命令/技术栈/步骤/工具/验证/产出）、目标（当前/未来/里程碑/验收/优先级/风险）、经历（事件/教训/决策/来源/时间/归档）。
- **块 = 段落**，具体记忆条目，**每格位默认取最新块（随本体全量常驻），按需召回历史块**。

> 注：**阶段（提案/审阅/拍板/实施/验收/归档）是独立维度（决策状态机），不是格位第二维**。四维正交 = 格位（总纲×本质）+ 阶段 + 时间档（经档/权档/行档）+ 来源（代码/LLM/人类），以代码 `类型定义_核心.rs`（2026-08-28 定稿）为准。

## 三、任务生命周期状态机

```
 待执行 ──→ 执行中 ──→ 已交付 ──→ 整理中 ──→ 已归档
              │  ↑ 验收驳回(≤3)      │              ↑ 债务-1
              ├──→ 失败(LLM 失败 fail loud)
              └──→ 废弃(多触发源，只回填教训)
```

| 状态 | 归属 | 推进者 |
|:--|:--|:--|
| 待执行 | 前端队列 | 事件：新任务 |
| 执行中 | 前端 worker | 4 分类流水线 |
| 已交付 | 交接点 | 前端 fire-and-forget |
| 整理中 | 后端 worker | 提炼回填 |
| 已归档 | 后端 | 债务清零 |
| 失败 | 前端 | fail loud，不回填 |
| 废弃 | 多触发源 | 见第八节 |

## 四、回填机制：交付才回填，两步分离

1. **回填时机 = 最终裁决通过后**（交付），期间用临时上下文；验收驳回则临时上下文继续累积，不回填。
2. **回填两步**：① LLM 提炼临时上下文 → 精炼块（去噪、格式化）；② 确定性归类写格位（写入时归类，O(1) 无损）。
   - **思考链分离（步骤 30 决策）**：响应层已把 `thinking`/reasoning_content 思考链与正文分离，下游只消费正文（`响应.内容`）；思考链是推理过程不落格位（回填只提炼正文，推理摘要不保留，避免稀释格位记忆）。
3. **按内容分类，一任务可回填多格位**（总纲×本质）：决策→目标×当前/优先级/风险；设计→执行×步骤；代码/交付物→执行×产出；验收→执行×验证；教训/复盘→经历×教训；规则修正→规则×规范；文档→外在×数据。
4. **元决策隔离**：关于格位/规则/架构本身的裁决，统一走 规则×规范（规范内容）+ 经历×决策（裁决事件），块加「元决策」注脚标记。

**代码已实现（回填两步 + 一任务多格位）**：内容类别 枚举（决策/设计/代码/验收/教训/规则修正/文档/元决策）+ 归类 映射（确定性，写入时归类）+ 回填器（提炼可注入闭包→归类写格位，元决策隔离自动带「元决策」注脚）+ 标注_注脚_格位。配套架构重塑：写入_格位_幂等 幂等键从「绑定任务」升级为「绑定任务 + 格位」，支持一任务多格位（同任务同格位覆盖、不同格位各自独立）。真实 LLM 提炼已接入：回填_交付产物（实现者池调真实/mock LLM 提炼，思考链在 moxing_fu 响应层剥离）+ 接入 4 分类流水线决策者最终裁决后（最终裁决通过才回填、验收驳回不回填，fire-and-forget 不阻塞前端）。

## 五、读路径：默认最新 + 按需召回历史

| 层 | 内容 | 注入时机 |
|:--|:--|:--|
| 36 格位本体 | 每格位最新块 | 全量常驻（下一轮起点） |
| 历史块 | 每格位更早的块 | 按需召回 |

历史召回四时机：①任务开始时决策者按关键词召回；②执行中遇阻主动下探；③验收有冲突召回对比；④决策冲突召回经人类最终验收授权的块裁决。召回方式 = 按四维坐标（总纲×本质×阶段×时间档×来源）确定性定位，不靠相似度排序；召回块进临时上下文，用完即弃。

**代码已实现（读路径 + 四时机接线）**：读路径 API 读取_相关格位（关键词表匹配总纲，无命中兜底全量）/ 读取_格位_分区（单格位全量，ID 降序）/ 读取_格位_玉玺优先（过滤废止、经人类最终验收授权的块优先、否则最近生效块）。四时机接线到 4 分类流水线（召回上下文 结构 + 组装召回上下文_按路径）：①任务开始关键词召回（读取_相关格位，注入全角色基础上下文；任务隔离：执行×步骤/验证/产出按绑定任务过滤，执行×命令/技术栈/工具 + 其余总纲跨任务共享）③验收对比（验收者额外注入 执行×验证 分区历史验收块，按绑定任务过滤 + 标注最新基线/历史，验收者产出差异对比四类：新增问题/已修复/回归/仍存在）④最终裁决（决策者终裁额外注入 目标×当前/规则×规范/经历×决策 经人类最终验收授权的块）。时机②遇阻下探已接线（最终裁决驳回 → 下探召回 经历×教训/执行×步骤 分区 → 重投 ≤驳回上限 轮）。验收驳回理由结构化：提取修订要求 从最终裁决内容提取可执行修订要求（致命修复/验收判据/复现命令/F1-F3 行），重投注入结构化修订要求而非全文，无结构回退原文前 20 行。驳回上限可配置（端点配置字段 打回上限，env LLM_打回上限，默认 1；契约上界「可循环验收驳回≤3 轮」保留，生产默认 1 因驳回重投当前无材料补充环节多轮重投无益，mock 固定 3 验证完整机制）。最终裁决判定结构化：解析最终裁决结论（驳回/不通过/驳回/暂不通过/不予通过/重做 → 驳回；通过/认可/准予/予以通过/同意 → 通过；无驳回词也无通过词 → 驳回，沉默=驳回保守语义，直击「框架空壳」不允许自评失真蒙混）。最终裁决质量：最终裁决调用失败（LLM 故障）fail loud 不重投，与「最终裁决驳回」（成功调用后裁决）严格区分——故障≠驳回，故障即退出码 4，驳回才重投 ≤上限轮。质量门禁三必填：最终裁决通过后校验 4 角色接力产出必须显式标注 decided_by（谁决策）+ falsifiable（可证伪命题），缺项即改判驳回（空壳产出不得通过；命名合规由决策者角色卡铁律 + 静态门禁脚本执行）。产出抽样评分：门禁通过后记录量化质量（决策契约三要素 decided_by/falsifiable/implements + 可复现 + 非空壳，0-100，阶段 D 出口标准）。替代 contains("打回") 脆弱字符串判定。读库统一 = 回填库（Some）或默认库，读写同一库。

## 六、双工流水线：前端执行 ∥ 后端整理

- 两个独立 worker 并发，事件驱动；前端交付后 fire-and-forget 发「交付事件」给后端，立即取下一任务，**从不 await 后端**。
- 前端只看前端队列与账本，后端只看债务队列与账本，唯一共享 = 账本（SQLite）+ 格位存储，靠状态标记协作、不直接通信。
- 触发型队列：新任务事件触发前端，交付事件触发后端，无活不空转。

## 七、任务债务：高峰攒、低谷还

- 债务 = 已交付数 − 已归档数，持久化 FIFO 队列。
- 高峰前端交付快则债务累积，低谷前端无任务则后端还债。
- 债务上限 + 降级：超限时后端跳过 LLM 提炼，**完整快照暂存临时上下文**（标记待补提炼），不丢质量。
- 债务监控：暴露水位/峰值/高峰低谷标记。

**代码已实现（双工流水线 + 先进先出债务队列 + 债务上限降级 + 债务监控）**：账本_债务队列（trait 第 5 账本方法，内存按登记顺序、SQLite 按 rowid 先进先出）+ 双工流水线 组件（前端_登记 / 前端_交付 即发即弃 / 后端_整理_一个 / 后端_整理_一个_带降级 / 债务 / 债务队列 / 债务上限 / 水位峰值 / 水位谷值 / 待补提炼 / 处于高峰 / 处于低谷）。降级语义：债务超上限→跳过提炼、完整快照暂存（待补提炼），否则正常归档。后端闭环已串联（§六）：双工流水线 加 后端_整理_一个_带整理（整理回调注入，超限或提炼失败→降级、否则正常归档），上层 后端整理 worker（双工账本 + 回填器格位 + LLM 提炼，同一 SQLite 文件两个连接共享）串成「前端交付→后端整理→提炼回填→归档→债务清零」端到端闭环，回填器复用 §四 的 LLM 提炼 + 归类写格位。前端交付→后端还债已做前后端职责分离：跑流水线_按连接 只做前端_登记并交付（债务+1，fire-and-forget），后端_还债_至清零（读债务队列循环 后端_整理_一个，债务=0 返回即无活不空转，失败只记日志不阻塞前端成功）由编排层 跑流水线_按后端 独立驱动，取代原「交付即回填」直接写格位路径。LLM 调用容错：单角色调用失败幂等重试一次（调用_带重试，仅超时/5xx/网络传输状态码0/解析错误可重试；4xx/额度耗尽/鉴权/配置错误立即 fail loud）。连接超时精确识别：ureq「timed out」+ Windows 连接超时 os error 10060/10061 → 错误::超时（真实 MiniMax 网络抖动常见）。失败归因分级：错误归因 把错误归为 超时/5xx/4xx/额度/鉴权/配置/解析/网络 八类标签，失败日志带「错误·标签」便于定位。债务残留语义：交付失败→未交付无债务；后端整理提炼失败→降级归档债务清零（快照暂存待补）；存储层错误→Err 传播债务保留可重试。

## 八、人类最终验收权（玉玺）权威分层与废弃

**人类最终验收权语义**：未授权不影响使用（未授权但可执行）；授权提升权威；**决策冲突时优先用经人类最终验收授权的块**。

| 块状态 | 是否进下一轮上下文 | 优先级 |
|:--|:--|:--|
| 生效 + 已授权 | ✅ | 最高（冲突优先取它） |
| 生效 / 待确认（未授权） | ✅ | 正常 |
| 废止 | ❌ | 只留审计，不喂回模型 |

**废弃多触发源**：①用户（项目负责人）指令废弃——最高权威，decided_by=项目负责人，授权；②决策者最终裁决判定废弃；③执行中 LLM 主动废弃——只能「建议」，仍需最终裁决确认。

**代码已实现（废弃多触发源 + 授权冲突优先）**：废弃触发源 枚举（界主/终裁/LLM建议）+ 废止_格位（界主/终裁直接废止盖手印、LLM建议 只标记待确认 + 注脚不改手印）+ 盖玉玺_格位（盖手印即确认生效）+ 读取_格位_玉玺优先（过滤废止块，同格位冲突优先取盖玉玺块）+ 错误::绑定任务不存在。

## 九、格位块元数据（对齐代码 + 契约新增）

**代码已实现（13 字段 = 12 原字段 + 块元数据 6 子字段）**：`id / 总纲 / 本质 / 阶段 / 档位 / 来源 / 内容 / 摘要 / decided_by / implements / hash / 软放弃`（12 原字段）+ `绑定任务 / 手印 / 注脚 / 生效状态 / 生效窗口 / 可证伪`（块元数据，可空列，见下）。

**契约 6 字段（已实现，SQLite 序列化落库）**：`绑定任务` 缺一即拒（`新建_契约块` 校验，`错误::缺失绑定任务`）；`手印 / 注脚 / 生效窗口 / 可证伪` 可为空（手印空=未授权，合法）；`生效状态` 缺省=生效（待确认/废止可显式标记）。

正文 = 单一格位、单一主题的精炼块，不含思考链与过程复述；缺 decided_by 或缺绑定任务必拒入库。

**绑定任务升格为幂等键（已实现）**：格位中枢::写入_格位_幂等 以 绑定任务 为查重键——同一任务重复写入复用旧 ID 覆盖内容、保留旧手印/注脚/生效状态（授权不因 AI 覆盖被清除），新任务走 新建_契约块。写入任务记忆 已改用幂等（绑定任务=任务摘要），治理「幻影完成」（同一任务重复执行产生重复记忆块）。

## 十、决策理由

本项目记忆模型是「AI 助手自动加载上下文」的核心机制。传统「对话历史上下文条」会无限膨胀、稀释重点、无法审计；本契约用「格位为唯一长期记忆 + 交付才回填 + 默认最新按需召回历史」替代之，配合「前端执行/后端整理双工流水线」让 LLM 不空转、前端不阻塞，且所有写入走「写入时确定性归类」的 O(1) 无损底座，不引入 RAG 式有损排序。

## 十一、追溯

本契约是 36 格位记忆模型（260828-格位稀缺原则）的落地执行层，遵循「36 上限、写入时归类、不可逆结果」的上位约束。所有未来记忆读写路径、流水线改造、债务机制变更，必须引用本契约的九节条款；冲突时以本契约的「人类最终验收授权优先」规则裁决。本契约由项目负责人确定、AI 自主落地（来源 LLM 会话档，未经人类最终验收授权），项目负责人日后确认可授权升为人类权威。
