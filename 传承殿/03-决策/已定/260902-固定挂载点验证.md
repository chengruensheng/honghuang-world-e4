## 一、为什么（问题：假验证）

「真实 LLM 产出代码 → 落盘 → 准圣验收」链路曾出现 **准圣 0/14 打回**：LLM 产出了代码文本，但无人落盘 → 准圣无证据可验。

初版 `--落盘` 方案把代码写到「孤立新文件」（如 `道韵/自举验证-园/自举生成_临时.rs`），暴露两个架构盲区：

1. **目录可能不存在** —— 目标路径指向了不存在的目录结构。
2. **落盘 ≠ 被验证** —— 孤立文件不属于任何 mod 树 / example，**cargo 根本不编译它** → 即便落盘成功，验证命令也是「空转」，准圣拿到的仍是假证据。这是「0/14 打回」的远端变体：不是没人落盘，而是**落了盘但没人编译**。

核心教训：**「文件存在」不等于「被编译」更不等于「被执行」**。验证必须绑定到 cargo 必然构建的目标上。

## 二、是什么（规则定义）

| 要素 | 规则 |
|:--|:--|
| 落盘目标 | 必须是 **Cargo.toml 预声明的 `[[example]]`**（或 bin/lib 内固定文件），不得是孤立新文件 |
| 挂载方式 | example 内 `include!("生成区.rs")` —— **静态挂载**，cargo 解析源文件时必然编译被包含文件 |
| 验证命令 | `cargo test -p <crate> --example <入口>` —— 真实编译 + 真实执行生成区内 `#[test]` |
| 生成区约定 | 只含 `#[test]` 测试与辅助 fn；全中文标识符；不得定义 `fn main` / `use` / 模块级 `//!` 注释 |
| 治理约束 | 被包含文件不能用 `//!`（与宿主冲突 → E0753），统一用 `//` 普通注释 |

## 三、怎么做（工程落地）

1. **宿主 crate** 在 Cargo.toml 预声明 example（`[[example]] 入口名 path = 生成验证入口.rs`）。
2. **入口 example**（不随任务变化）：`include!("生成区.rs");` + 空 `fn main(){}`。
3. **生成区.rs**（唯一落盘覆写点）：默认空占位 `#[test] fn 默认占位_生成区为空() {}`，LLM 产出覆写为实现 + 测试。
4. **执行器** `真任务 --落盘`：落盘工单只允许覆写 生成区.rs，验收命令 = `cargo test -p 规则府 --example 生成验证入口`（必然编译 → 真实执行 → 准圣基于证据验收 → 道祖终裁 → 退出码 0）。
5. **回归纳入**：门禁 3 单元测试 + CI 双平台补 `cargo test -p guize_fu --example 生成验证入口`（`--lib` 不覆盖 example；`--all-targets` 只覆盖编译、不覆盖测试执行）。
6. 治理：命名唯一性门禁要求殿/阁/园目录名全局唯一；example 必须在 Cargo.toml 预声明否则 cargo 不编译。

## 四、验证
