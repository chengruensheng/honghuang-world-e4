## 二、6 层结构与 9 根的交叉

每个根维度下，按 6 层组织：
- **域**：语义分组（如"基础设施 - 域"）
- **府**：lib crate（唯一编译单位，Service Definition 暴露点）
- **殿/阁/园**：层层递进（能力只在园落地）

### 服务清单（按 9 根维度 + 6 层）

### 鸿蒙（核心地基）

| 服务 | 职责 |
|:--|:--|
| 插件上下文 | Service Definition 注册表 + 查找 |
| 跨维事件总线 | 三类事件 + Waterfall/Serial |
| 记忆承载 | 36 格位 + 3 档投影 + 3 源记录 |
| 状态共享 | 进程级状态读写 |
| 观测探针 | 24 项事件通道埋点 |
| 日志记录 | tracing 定制封装 |
| 流水线驱动 | 4 阶段状态机（道祖→圣人→大罗→准圣→道祖） |
| 任务执行 | LLM 池 + 工具循环 + 4 分类角色卡 |
| 配置管理 | 密钥/模型配置注入 |

## 三、4 分类的工程落位

```
道祖级 ─→ 流水线驱动 - 府/天层-主控-殿/道祖级/
         ├── 追问引擎（02-概念/追问/05-追问.md）
         ├── 化要求 / 派遣 / 终裁 / 定档
         └── 多 LLM 投票（关键决策）

圣人级 ─→ 任务执行 - 府/角色-卡册-殿/圣人卡/
         ├── 设计 / 评审
         └── 评审四元组

准圣级 ─→ 任务执行 - 府/角色-卡册-殿/准圣卡/
         ├── 六维验收（前 4 维机械 + 后 2 维 LLM）
         └── 打回决策（独立判定）

大罗金仙级 ─→ 任务执行 - 府/角色-卡册-殿/大罗卡/
             ├── 实现（按道分工：性能/数据/接口/监控）
             └── 路径前缀校验（不越道）
```
