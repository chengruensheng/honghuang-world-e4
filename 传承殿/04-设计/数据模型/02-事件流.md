# 02-事件流.md

> **数据模型·事件流**——三类事件 + hash 链 + frozen outcome。

## 一、事件结构

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct 事件 {
    pub id: 事件ID,                    // 唯一标识
    pub 类型: 事件类型,                 // Session | Agent | Capability
    pub 模式: 事件模式,                 // Waterfall | Serial
    pub prev_hash: Hash,               // 上一个事件的 hash
    pub 内容: serde_json::Value,
    pub decided_by: String,            // 人类标识符
    pub 时间: Timestamp,
    pub hash: Hash,                    // 当前事件的 hash
    pub immutable: bool,               // frozen outcome 标记
}

#[derive(Debug, Clone, Copy, Serialize, Deserialize)]
pub enum 事件类型 {
    Session,      // 持久化事件
    Agent,        // live 事件
    Capability,   // policy 事件
}

#[derive(Debug, Clone, Copy, Serialize, Deserialize)]
pub enum 事件模式 {
    Waterfall,    // 必须 next()
    Serial,       // 独立拦截点
}
```

## 二、Hash 链

每个事件包含：
- `prev_hash`：上一个事件的 hash
- `hash`：当前事件内容 + prev_hash 的 sha256

### 写入流程

```rust
pub fn 写入事件(事件: 事件, 上一个事件: Option<&事件>) -> Result<事件ID, 错误> {
    let prev_hash = 上一个事件.map(|e| e.hash).unwrap_or_default();
    let mut 新事件 = 事件;
    新事件.prev_hash = prev_hash;
    新事件.hash = sha256(&serde_json::to_vec(&新事件)?);

    // append to jsonl
    append_to_jsonl(&新事件)?;

    Ok(新事件.id)
}
```

### 验证流程

```rust
pub fn 验证事件流(jsonl_path: &Path) -> Result<(), 错误> {
    let mut prev_hash = Hash::default();
    for line in read_lines(jsonl_path) {
        let 事件: 事件 = serde_json::from_str(&line)?;
        if 事件.prev_hash != prev_hash {
            return Err(错误::哈希链断裂);
        }
        let 期望_hash = sha256(&serde_json::to_vec(&事件)?);
        if 事件.hash != 期望_hash {
            return Err(错误::哈希不匹配);
        }
        prev_hash = 事件.hash;
    }
    Ok(())
}
```

## 三、3 类事件

### Session 事件（持久化）

- append 到事件流
- broadcast 通过总线
- 适用：事实必须穿越 reload
- 例：化要求完成、验收打回、定档完成

### Agent 事件（live）

- 携带 live Agent 对象
- 适用：观察或拦截 in-flight 工作
- 例：当前阶段切换、当前任务执行进度

### Capability 事件

- attach policy + adapter 到接缝
- 适用：fs/* / tools/* / telemetry/*
- 例：工具调用前置校验、写入权限拦截

## 四、2 模式

### Waterfall

```rust
pub trait Waterfall监听器 {
    async fn 处理(&self, ctx: &mut Waterfall上下文) -> Result<(), 错误>;
}

pub struct Waterfall上下文 {
    pub next: Box<dyn Fn() -> Pin<Box<dyn Future<Output=Result<(), 错误>>>>>
}

impl Waterfall上下文 {
    pub async fn 调下一步(&mut self) -> Result<(), 错误> {
        (self.next)().await
    }
}
```

### Serial

独立拦截点，不调 next()：

```rust
pub trait Serial监听器 {
    async fn 处理(&self, 事件: &事件) -> Result<Serial结果, 错误>;
}

pub enum Serial结果 {
    通过,
    拒绝(String),    // 拒绝原因
    拦截(String),    // 拦截但不阻塞
}
```

## 五、不可改（frozen outcome）

```rust
impl 事件 {
    pub fn 标记不可改(&mut self) {
        self.immutable = true;
    }

    pub fn 修改(&mut self, 新内容: serde_json::Value) -> Result<(), 错误> {
        if self.immutable {
            return Err(错误::不可改("事件已 frozen"));
        }
        self.内容 = 新内容;
        Ok(())
    }
}
```
