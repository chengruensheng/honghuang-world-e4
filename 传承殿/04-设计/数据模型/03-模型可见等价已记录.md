## 〇、设计目标

让流水线 LLM 请求真正注入记忆（接线），且注入内容可审计（断言「注入文本 ⊆ 持久库全部记忆文本」）。
一句话不变量：「进了 LLM 上下文的记忆，必须能从持久库（SQLite）逐条重建」——即 DSH 论文的「Model-visible ⟺ logged」落到本项目的记忆承载府。

断点结论：记忆「读取」与「注入」之间断链——读取任务相关记忆_持久 已实现且有测试，但 run_pipeline_with_backend 从不调用它；且即使调用，注入侧 [范畴] 与审计侧 [范畴·阶段] 格式不一致，导致「注入文本 ⊆ 查全部记忆」的直接字符串断言必然假阴性（[程序] X 不是 [程序·实施] X 的子串）。

## 二、设计决策（4 条）

### 决策 1：注入通道 = 请求.消息列表（新增一条系统消息）

- 依据证据 #2：请求 无独立「上下文」字段，消息列表 是唯一内容通道。
- 具体字段（待 t1 复核确认，本设计给出确定默认）：注入到 请求.消息列表，在「角色卡系统消息」与「任务用户消息」之间插入一条 消息::系统，内容为持久记忆文本（带分隔头）。
- 注入内容逐字来自 读取任务相关记忆_持久 返回值（Vec<String> 用换行拼接），不做任何改写/精炼/合成——这是不变量成立的前提（见决策 4 的「由构造成立」论证）。

### 决策 2：规范文本统一 = [范畴·阶段] 内容

- 把 格式化成文（记忆读取_核心.rs:39-45）从 [{}] {}（仅范畴）升级为 [{}·{}] {}（范畴·阶段），与 查全部记忆、读取_三档投影、读格位仓库 完全一致。
- 效果：读取任务相关记忆_持久(库, t) 的返回值成为 查全部记忆(库) 的子集（读取侧按范畴过滤，最多返回全部），子集断言「注入文本 ⊆ 查全部记忆」由字符串成员关系精确成立。

### 决策 3：流水线只走持久版；内存种子版标记「演示专用」

- 流水线 run_pipeline_with_backend 只调用 读取任务相关记忆_持久(默认记忆库路径, 任务标识)。
- 读取任务相关记忆（内存种子版）保留，但加注释：「演示专用」——进程内内存库，退出即丢，不可审计；流水线真实注入走 读取任务相关记忆_持久。
- 理由：内存版用 SQLite存储::内存新建()，进程退出即销毁，没有持久库可回查——「注入文本 ⊆ 持久库全部记忆文本」的「持久库」半边对它不成立，审计函数对同一数据源无法回溯。若流水线走内存版，falsifiable 命题 F2（注入可回查）永远无源可查，命题退化为不可证伪。

### 决策 4：注入后立即审计（debug_assert + 日志回显）

- 在请求组装前、调用器.调用 前，对注入文本执行审计断言（见 §五），并把注入文本写入流水线日志，使注入在 命令结果.输出 中可观测（mock 路径也可见，因 mock 的 发送 忽略请求内容、不回显）。
- 生产路径用 debug_assert!（release 不崩）；测试路径用显式 assert! + 审计函数返回值断言。

## 四、接线伪码（只示意，不落地）

```
fn run_pipeline_with_backend(任务标识: &str, 模式: 后端模式) -> 命令结果 {
    use moxing_fu::{请求, LLM调用器};
    // （决策 1/3）任务前：从持久库读取相关记忆——唯一注入源
    let 相关记忆 = 读取任务相关记忆_持久(默认记忆库路径, 任务标识);

    // （决策 4）注入前审计：每条注入文本必须可回查
    let (全部可回查, 缺失) = 审计_注入可回查(默认记忆库路径, &相关记忆);
    debug_assert!(全部可回查, "注入记忆不可回查：{:?}", 缺失);

    // （决策 4）日志回显，使注入在 命令结果.输出 中可观测
    日志.push_str(&format!("[注入记忆] {} 条", 相关记忆.len()));
    for m in &相关记忆 { 日志.push_str(&format!("  {}", m)); }

    // ...（调用器构造逻辑不变）...

    let 记忆上下文 = 拼接记忆上下文(&相关记忆); // 含分隔头，如 [持久记忆]
    for 池名 in 池顺序.iter() {
        let req = 请求::新建("", vec![
            moxing_fu::消息::系统(format!("你是 {} 角色卡", 池名)),
            moxing_fu::消息::系统(记忆上下文.clone()),   // ← 注入点（决策 1）
            moxing_fu::消息::用户(format!("任务：{}", 任务标识)),
        ]);
        match 调用器.调用(池名, &req) { /* 不变 */ }
    }
    // ...
}
```

## 五、可审计不变量与断言位置

### 不变量（精确定义）

设 库 = 默认记忆库路径，一次流水线运行中：
- 注入文本 = 拼接记忆上下文 展开后的逐条 Vec<String>（即 读取任务相关记忆_持久(库, 任务标识) 的返回值，未改写）；
- 全量文本 = 查全部记忆(库)。

不变量：注入文本 ⊆ 全量文本（每条注入文本都 ∈ 全量文本）。

由构造成立的充分条件（设计保证，非运行时侥幸）：
1. 注入逐字来自 读取任务相关记忆_持久（决策 1，不做改写）；
2. 读取任务相关记忆_持久 内部走 读取_相关格位（返回 查_全部() 的子集），再经 格式化成文；
3. 格式化成文 与 查全部记忆 用同一规范文本 [范畴·阶段] 内容（决策 2）。

满足 1-3 后，不变量是集合包含的必然结果；审计函数只是把它从「构造保证」升级为「可观测断言」，任何回归（格式漂移、改写注入、凭空塞内容）都会触发「缺失清单非空」。

## 七、待 t1 复核项（本设计已给确定默认，不阻塞 t4）

1. 注入字段：本设计定为 请求.消息列表 的中间 消息::系统（唯一内容通道，连接.rs:43-48）。t1 若评估「任务描述应含关键词表命中信息」或「注入应走 读取_三档投影 而非 读取_相关格位」，需在 t4 落地前回传修正。
