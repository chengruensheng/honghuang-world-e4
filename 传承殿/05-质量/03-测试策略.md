# 03-测试策略.md

> **鉴层·测试策略**——概念测试而非实现测试。

## 一、核心原则

### 概念测试 > 实现测试

> "测试必须验证概念而非实现。如果换一种实现方式，测试还能通过吗？如果不能，说明测的是实现而不是概念。"

示例：
- ❌ 实现测试：`#[test] fn 测试_化要求_函数() { assert_eq!(化要求("输入").unwrap(), 期望输出); }`
- ✅ 概念测试：`#[test] fn 测试_化要求_追问引擎触发() { let r = 化要求("模糊想法").unwrap(); assert!(r.经过追问); }`

### 测试覆盖哲学概念

每个哲学概念必须有对应测试：
- 可插拔 → 测试插件替换不影响其他插件
- 流水线 → 测试不可跳层不可反序
- 记忆 → 测试三档投影
- 事件流 → 测试 hash 链 + frozen outcome
- 追问 → 测试 4 问题触发
- 规则注册表 → 测试 RULE_COUNT 派生
- frozen outcome → 测试不可改
- LLM 不直改 → 测试 decided_by 缺失则拒

## 二、测试层级

### L1：单元测试

- 验证单个函数 / 模块行为
- 覆盖率 ≥ 80%
- 工具：`cargo test`

### L2：集成测试

- 验证模块间协作
- 流水线不可跳层不可反序的端到端测试
- 工具：`cargo test --test 集成`

### L3：契约测试

- 验证插件 manifest 契约
- 验证事件流 schema
- 验证工具接口契约
- 工具：`cargo test --test 契约`

### L4：可证伪条件测试

- 验证 falsifiable 条件可被机械判定
- 每个决策文档都有对应测试
- 工具：自定义 harness

## 三、测试编写规则

### 规则 1：测试哲学概念

```rust
#[test]
fn 测试_插件替换不影响其他插件() {
    let ctx = 测试上下文::new();
    let 插件A = 加载插件("A");
    let 插件B = 加载插件("B");

    ctx.注册(插件A);
    ctx.注册(插件B);

    let _before = 查找服务::<dyn 插件B契约>(&ctx).unwrap().调用();

    // 替换 A
    let 新A = 加载插件("A-v2");
    ctx.替换("A", 新A);

    let _after = 查找服务::<dyn 插件B契约>(&ctx).unwrap().调用();
    assert_eq!(_before, _after);  // B 不受 A 替换影响
}
```

### 规则 2：测试不可跳层

```rust
#[test]
fn 测试_流水线不可跳层() {
    let mut sm = 流水线::new();
    sm = 推进(sm, 事件::化要求完成(...)).unwrap();
    sm = 推进(sm, 事件::设计开始).unwrap();
    // 跳过实现，直接到验收
    let r = 推进(sm, 事件::验收开始);
    assert!(r.is_err());  // 必须先经过实现
}
```

### 规则 3：测试 decided_by 强制

```rust
#[test]
fn 测试_写入经档必须decided_by() {
    let mut mem = 记忆::new();
    let r = mem.写入经档("内容", vec![证据], "");  // 空 decided_by
    assert!(r.is_err());

    let r = mem.写入经档("内容", vec![证据], "界主");  // 有效
    assert!(r.is_ok());
}
```
