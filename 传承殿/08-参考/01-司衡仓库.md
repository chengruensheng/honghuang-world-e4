## 三、6 柱石（道-法-术-鉴-应-元）

来源：`glossary/zh.yml`

| 柱石 | 定义 |
|:--|:--|
| **道** | 代码工程的因果必然性。四条：发散自-然收敛必-为、意图先于代码、代码自晦意图必复、规约与实现必有间隙 |
| **法** | 从道推导的方法论原则。收敛五法：顺因、有度、知止、损补、顺势 |
| **术** | 法的工程化展开。Spec-Coding、三机体系、F/G/J 法则体系 |
| **鉴** | 检验道层主张的方法论。反推九段式、诗与理区分、可证伪条件设定 |
| **应** | 居中不动以应万变。应辨（当前形态）/ 应几（演进方向） |
| **元** | 道之所由立。四元：存在论 / 生成论 / 认识论 / 方法论 |

## 四、5 工程基线

1. **确定程序是治理操作唯一执行者**（LLM 只生成符号材料）
2. **信息洪流是旧仓失败根因**
3. **人类只看异常，不看原始日志**
4. **可验证性约束**（操作可追溯/结果可机械校验/历史不可篡改）
5. **治理延伸是减少 LLM 参与**

## 五、4 禁止条款

1. **LLM 不可直改知识包**
2. **不可复现多 Agent 交互不可作治理决策依据**
3. **治理操作必入事件流，留痕不可篡改**
4. **人类只通过视图介入，不看原始日志**

### 6.3 关键决策：追问引擎

> "司衡覆盖治理链的中游（文档验证）和下游（AST 对齐），但上游缺失：用户意图在变成 proposal 之前，没有机制帮助用户精确化自己的意图。"

4 问题（对应道二/顺因/有度/知止）：
1. **道二**：你的意图是什么？（意图先于代码）
2. **顺因**：这个提案的因果方向是什么？
3. **有度**：规则数 / 严格度是否与风险成正比？
4. **知止**：哪些事情不做？

关键洞察：**追问引擎不调 LLM 生成内容，只生成追问提示词**。

> "追问引擎持有 API key，自己调 LLM 生成内容——违反核心定位：司衡不生成代码/文档，只验证。而且验证者与生成者做在同一进程内，鉴的公信力减弱。"

### 6.4 关键决策：流程推进层

> "司衡每份文档独立管理 stage，但文档之间的推进依赖纯手工操作，导致系统性断链。"

两层状态机：
- **ProjectState**（项目层）：suggest_next_action
- **Document.stage**（文档层）：1/3 提案 → 2/3 审阅 → 3/3 拍板
