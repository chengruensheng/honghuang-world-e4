## 三、实施任务（3 天）

### Day 1：CLI 三条真命令

- `mingling_caozuo_fu` 扩展：
  - `init`：环境检查（rustc/cargo 存在 + 配置文件可写） + 输出"就绪"
  - `run --task=<task_id>`：从 `任务执行-府` 拉取任务 → 调 `liushuixian_qudong_fu` 跑流水线
  - `status`：健康检查（workspace metadata + test pass + clippy 0 warning）
- 参数解析：纯 Rust，模式匹配 `args[0]` 与 `args[1..]`；不引 clap
- 中文友好：UTF-8 参数 + 路径处理

**单元测试**：init/status 无副作用测试 + run 命令分发测试。

### Day 2：e2e 任务 + 集成测试

- 在 `mingling_caozuo_fu` crate 内部新增 `tests/e2e.rs`：
  - 1 个完整 e2e：发布任务 "修复 typo" → 道祖化要求 → 圣人设计 → 大罗执行 → 准圣验收 → 道祖终裁
  - 拒绝路径 e2e：跳层（道祖→准圣直接验收）= 拒绝 + 报错
  - 循环打回 e2e：准圣打回大罗 3 次 → 第 4 次自动升级道祖终裁

## 四、命名与代码风格契约（按模板）

- **目录**：乾坤/呈现 - 域/命令操作 - 府/（维度/域/府 3 段）
- **Rust lib 名**：拼音 snake_case ASCII（mingling_caozuo_fu 不变）
- **文件**：`入口.rs`（无 src/ 平铺）
- **注释**：中文，含决策锚 + 关联文档
- **参数解析**：纯 Rust（`std::env::args()`），不引 clap 等外部依赖
- **测试**：每个命令至少 3 个测试（help / valid / invalid）
