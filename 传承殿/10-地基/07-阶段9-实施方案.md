## 三、实施任务（5 天）

### Day 1-2：4 类指标 + 监控

- 新建 `道果树/质量门禁-域/监控-府/` crate（jiankong_fu）
- 4 类指标结构：
  - 可用性：uptime 百分比 + 在线/离线状态
  - 性能：p99 延迟 + QPS + 错误率
  - 正确性：falsifiable 通过率 + 单元测试通过率
  - 资源：内存 + CPU + 磁盘 + 文件句柄
- `指标` struct：名称 + 值 + 阈值 + 时间戳
- `监控报告` struct：当前所有指标快照
- 单元测试：4 类指标可采集

### Day 3：4 级告警

- 4 级告警 enum：P0（紧急）/ P1（重要）/ P2（次要）/ P3（提示）
- `告警` struct：级别 + 来源 + 指标 + 触发时间 + 状态（已触发/已确认/已解决）
- `告警引擎`：
  - 接收指标变化 → 匹配阈值 → 触发告警
  - P0 立即升级到道祖级（人类介入）
  - P1 升级到圣人级（设计介入）
  - P2 升级到准圣级（验收介入）
  - P3 升级到大罗级（执行介入）
- 单元测试：4 级告警 + 升级路径

### Day 4：4 级应急流程

- 4 级应急 enum：道祖级/圣人级/准圣级/大罗级
- `应急流程` struct：级别 + 触发条件 + 动作 + 负责人
- 触发自动响应（auto）或半自动（semi-auto）或手动（manual）
- 与升级路径集成：P0 → 道祖级应急（人类介入）；P1 → 圣人级（设计）

### Day 5：端到端 + commit

- 4 类指标 + 4 级告警 + 4 级应急 e2e
- 巡世分级阈值可配置
- commit phase end
