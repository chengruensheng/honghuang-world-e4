## 二、v4 阶段候选（5 个）

### 阶段 15：性能基准 + 内存占用回归

- **目标**：单任务 e2e < 5s / 内存 < 200MB
- **依赖**：阶段 12 决策契约已接入
- **falsifiable**：5 个性能基准脚本 + 基准线值
- **估计**：1 天

### 阶段 16：架构校验 Rust 化（jiankong-工具）

- **目标**：替代 PowerShell 脚本 → 11/11 全绿
- **依赖**：阶段 13/14 验证-架构.ps1 已有 11 项逻辑
- **falsifiable**：jiankong-工具 11/11 全绿 + 一键全验集成
- **估计**：0.5 天

### 阶段 17：真实 LLM 接入 + 端到端回归

- **目标**：用真实 LLM（DeepSeek/OpenAI）替换 mock + e2e 回归
- **依赖**：阶段 7 moxing_fu 已落地（HTTP + LLM 池）
- **falsifiable**：API key 注入 + 1 个真实任务跑通 + 工具调用 ≤ 5
- **估计**：2 天

### 阶段 18：多 agent 协同 / 道祖级调度

- **目标**：道祖级可同时管理多个大罗级执行任务
- **依赖**：阶段 4 RULE_REGISTRY + 阶段 10 升级
- **falsifiable**：道祖级同时调度 ≥ 2 大罗级任务 + 全部完成
- **估计**：3 天

### 阶段 19：v1 候选（release 前稳定化）

- **目标**：v1.0.0 release + 文档完整 + 真实部署
- **依赖**：v3 + v4 全部完成
- **falsifiable**：v1.0.0 tag + README 完整 + 部署文档 + ≥ 10 个真实任务跑通
- **估计**：5 天

## 三、推荐顺序

阶段 16 (架构校验 Rust 化) → 阶段 17 (真实 LLM 接入) → 阶段 15 (性能基准) → 阶段 18 (多 agent) → 阶段 19 (v1)

理由：
- 阶段 16 解决当前 PS 局限（中文路径）
- 阶段 17 是真正价值点（mock → real）
- 阶段 15 在 real LLM 稳定后做基准更准确
- 阶段 18 需要 17 的稳定基础
- 阶段 19 是收口

## 四、命名哲学

每阶段命名遵循"哲学层 → 概念层 → 工程层"三段推导：
- 性能 → 评估 → 评估-府（chengben_fu）
- 架构 → 校验 → 校验-工具（jianyan_tool）
- 接入 → 实时 → 实时-府（shishi_fu）
- 协同 → 调遣 → 调遣-府（diaoqian_fu）
- 收口 → 终裁 → 终裁-府（zhongcai_fu）

## 五、风险
