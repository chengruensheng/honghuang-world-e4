## 二、调遣-府切分方案（2 殿 × 4 阁 × 4 园）

### 2.1 命名映射（祖孙不同名 + 全局唯一）

```
调遣-府/
├── 任务-数据-殿/
│   ├── 状态-枚举-阁/
│   │   └── 状态枚举-园/          ← 任务状态 enum
│   └── 任务项-定义-阁/
│       └── 任务项-园/            ← 任务项 struct + impl（新建/标记）
└── 调度-执行-殿/
    ├── 调度器-核心-阁/
    │   └── 调度器-园/            ← 调度器 struct + impl（新建/添加/全部完成）
    └── 运行-循环-阁/
        └── 循环-驱动-园/        ← impl 运行_全部 + 错误隔离
```

祖孙校验（去后缀后两两不同）：任务-数据/状态-枚举/状态枚举 ✓；调度-执行/调度器-核心/调度器 ✓；调度-执行/运行-循环/循环-驱动 ✓。

### 2.2 内容分布

| 文件 | 承载 | 测试归属 |
|:--|:--|:--|
| 状态枚举-园 | `任务状态` enum（待执行/执行中/已完成/失败）| 级别变体数匹配 → 调度器/任务项-园 |
| 任务项-园 | `任务项` struct + impl（新建/标记_执行中/标记_完成/标记_失败）| 任务项_新建 / 状态机 / 失败记录 |
| 调度器-园 | `调度器` struct + impl（新建/添加/全部完成）| 添加任务 / 双任务并行模拟 |
| 循环-驱动-园 | impl 运行_全部（含错误隔离，跨 调度器 + 任务项）| 运行全部_全部成功 / 错误隔离 |

跨园引用：循环-驱动-园 用 `use crate::任务_数据_殿::任务项_定义_阁::任务项;`、`use crate::调度_执行_殿::调度器_核心_阁::调度器;`。

### 2.3 入口.rs 改造

```rust
//! 调遣-府 - v4 阶段 18 多 agent 协同（道祖级调度器）

#![allow(non_snake_case)]

#[path = "任务-数据-殿/模块.rs"]
pub mod 任务_数据_殿;
pub use 任务_数据_殿::{任务状态, 任务项};

#[path = "调度-执行-殿/模块.rs"]
pub mod 调度_执行_殿;
pub use 调度_执行_殿::调度器;
```
